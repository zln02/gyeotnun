4. ★ 덤 — 복원 리허설이 자기 결함을 잡았다
===========================================

  이번 턴에서 검증용 checks 1행을 delete_rows.py 로 지우려 했더니 **리허설이 막았다.**

      ★★ 중단 — 백업으로 되살릴 수 없다. 아무것도 지우지 않았다.

  옳게 막은 것이다. 원인은 내 **백업 형식**이었다. CSV 를 쓸 때 파이썬 기본
  str() 을 써서 JSON 컬럼(`checks.history`)이 **파이썬 repr**(작은따옴표)로 저장됐다.
  그 CSV 로는 JSON 컬럼을 되살릴 수 없다.

      ['질문1: 이 내용을 어디서 …']      ← repr. JSON 이 아니다
      ["질문1: 이 내용을 어디서 …"]      ← 이래야 복원된다

  → `_encode()` 를 넣어 dict/list 는 `json.dumps` 로 쓰게 고쳤다. 다시 돌리니
    "복원 리허설 통과 — 1행 복원 · 체크섬 d8de18e8 일치" 로 지나갔고 삭제됐다.

  ★ 리허설을 넣은 이유가 정확히 이것이다. **파일이 만들어진 것과 되살릴 수 있는
    것은 다르다.** 어제 events 테이블(JSON 컬럼 없음)에서는 통과했기 때문에,
    리허설이 없었다면 JSON 컬럼이 있는 테이블에서 "백업이 있다"고 믿은 채
    복원 불가능한 파일만 쌓였을 것이다.
  ★ 규칙을 만든 다음 날 그 규칙이 내 실수를 잡았다. 기록해 둔다.
