곁눈 - 오매칭/환각 재현 조사 (2026-08-08)
조사 대상: ① OCR 에 없는 "은행명" 을 묻는 질문이 생성된 건
          ② 대출 이미지에 금융위원회 카드뉴스가 근거로 나온 건
★ 코드 변경 없음. 재현과 원인 추적만 수행. 컨테이너에 넣은 재현 스크립트는 조사 후 삭제함.


0. 재현 대상 특정
--------------------------------------------------------------------
평가셋 30건 중 대출 이미지는 B07 한 건이다.
  B07 (경계) GT: "은행 직원이 정부지원 대출상품을 설명하고 지점 방문 상담을 권함."
이 이미지를 라이브와 같은 조건(OCR_PROVIDER=local, PaddleOCR)으로 돌린 결과
금융위원회 카드뉴스(fsc.go.kr)가 근거로 나왔다 → ②와 일치하므로 같은 건으로 본다.
※ 태희 님이 실제로 올린 이미지 파일 자체는 확인하지 못했다(_MEMORY_STORE 는 프로세스
   메모리라 사후 조회 불가, 로그에는 본문을 남기지 않는다). B07 로 재현한 결과다.

실제 OCR 출력(로컬 PaddleOCR):
  '은행 직원이 정부지원 대출상품을설명하고지점방문상담을권'


1. 질문 생성 입력에 은행명이 있었는가 → 없다
--------------------------------------------------------------------
'은행' 이라는 보통명사는 있다. 그러나 고유명사(○○은행)는 없다.
전화번호·명함·문자·발신번호도 입력에 전혀 없다.

LLM 에 실제로 들어간 user 메시지 전문:

  [사용자가 받은 글]
  은행 직원이 정부지원 대출상품을설명하고지점방문상담을권

  [확인이 필요한 지점]
  - 공식 자료와 대조했습니다: 보건복지부·한국사회보장정보원 - 소상공인지원(융자)
  - 이전에 확인된 사기 수법과 비슷합니다 (오판유형: 권위자사칭 수용형, 숫자·조건 혼동형).
  - 이전에 확인된 사기 수법과 비슷합니다 (오판유형: 권위자사칭 수용형).

  [사용할 수 있는 실제 출처 - 이 목록 밖의 링크는 절대 쓰지 말 것]
  - 소상공인지원(융자) | 보건복지부·한국사회보장정보원 | https://www.bokjiro.go.kr/...
  - 공식/금융위원회 | fsc.go.kr | https://www.fsc.go.kr/no040101?cnId=1610
  - 공식/경찰청·투자리딩방 사기유형 | police.go.kr | https://www.police.go.kr/...

즉 입력 어디에도 은행명은 없다.


2. 그러면 은행명은 어디서 왔는가 → LLM 환각. 3회 재생성 전부 재현됨
--------------------------------------------------------------------
같은 입력으로 3회 생성한 결과(전부 가드레일 통과):

 [1] "그 은행 직원이 소속 은행 이름과 직원 이름, 직통 전화번호를 정확히 알려주셨나요?
      방문 상담을 권한 지점이 실제로 존재하는 지점인지 은행 대표번호로 직접 확인해
      보실 수 있을까요?"
 [2] "그 은행 직원이 말한 대출상품 이름을, 은행 대표번호(직접 검색한 번호)로 전화해서
      실제로 있는 상품인지 물어보실 수 있을까요?"
 [3] "그 은행 직원분의 소속과 이름을 은행 대표 전화번호로 직접 전화해서 확인해
      보셨을까요? 명함이나 문자에 적힌 번호 말고, 인터넷에서 검색한 은행 공식
      대표번호로 걸어보시는 게 좋아요."

3/3 모두 "소속 은행 이름 / 대표번호" 를 전제로 물었고, [3]은 입력에 없는
**명함·문자**까지 지어냈다. 우연이 아니라 이 입력에서 반복되는 패턴이다.

환각을 밀어 준 요인 3가지 (전부 우리가 넣은 것):
  (a) 사기사례 신호 2건이 "권위자사칭" 이라는 프레임을 준다 → 모델이 "사칭 여부를
      확인하는 질문" 을 만들려 한다. 사칭 확인의 정석은 '소속·이름·대표번호 대조'다.
  (b) few-shot 예시 1건이 "글 안에서 기관 이름을 한번 찾아봐 주세요" 라는 형태를
      정답으로 가르친다 → 기관 자리에 입력에 있던 '은행' 이 대입된다.
  (c) 입력이 25자짜리 상황 설명문이라 근거가 빈약하다. 빈 자리를 모델이 메운다.

★ 검색된 문서에서 온 것은 아니다. references 3건 어디에도 은행명은 없다.
★ 템플릿(FALLBACK_QUESTION)도 아니다. fallback=False 로 정상 생성 경로였다.


3. 근거 없는 단정/전제를 왜 가드레일이 못 막았나 → 그런 검사가 없다
--------------------------------------------------------------------
validate_question() + _screen_payload() 가 하는 검사는 3가지뿐이다.
  1) 금지어(FORBIDDEN_PATTERNS 17개: 가짜/사기/확실합니다 …) → 판정 표현 차단
  2) URL 화이트리스트 → references 밖의 URL 제거
  3) 문장 수 ≤ 2

"입력에 없는 사실을 전제로 깔았는가" 를 보는 검사는 **없다**.
실제로 넣어 본 결과:

  PASS ✅ "문자에 적힌 국민은행 대표번호가 실제 번호와 같은지 확인해 보셨나요?"
  PASS ✅ "명함에 적힌 직통 전화번호 말고 은행 공식 대표번호로 걸어보셨을까요?"
  PASS ✅ "이 안내는 금융위원회가 발표한 내용입니다. 맞는지 확인해 보시겠어요?"
  BLOCK ❌ "이 문자는 사기입니다."  ← 금지어에 걸린 유일한 문장

세 번째가 특히 문제다. 근거 URL 없이 기관을 단정해도 통과한다.
게다가 이번 3회 생성은 모두 evidence_refs 에 fsc.go.kr 을 달았는데, 이 URL 은
references 목록에 있으므로 화이트리스트를 **정상 통과**한다. 링크가 그 주장을
뒷받침하는지(주제 적합성)는 검사하지 않는다 → "형식상 근거 있는 환각" 이 된다.

즉 가드레일은 설계상 '판정 억제' 장치다. '사실 근거' 장치가 아니다.
막지 못한 게 아니라, 막는 항목이 아니었다. (버그 아님 / 설계 공백)


4. 금융위원회 카드뉴스는 어디서 왔나 → 0.679 를 거치지 않았다
--------------------------------------------------------------------
★ 결론: 유사도 임계값 0.679 와 무관한 경로다. 임베딩 검색 결과가 아니다.

경로별 실측:

 (A) 공식문서 임베딩 검색 (0.679 가 적용되는 유일한 경로)
     1위 0.6470  소상공인지원(융자)          ← EMBEDDING_MIN_SCORE 0.6155 이상이라
     2위 0.6067  햇살론youth 보증사업            참고자료로는 표시, 그러나
     3위 0.6058  국가유공자등대부지원            CONFIDENT 0.6790 미만 → 확신 근거 아님
     → official_confident = False (설계대로 동작함)

 (B) 공식문서 BM25 (임계값 12.0)  → 매칭 0건

 (C) 사기사례 코퍼스 SCAM_CASES  ← ★ 금융위 URL 은 여기서 나왔다
     case=C09  수법일치=1(loan_bait)  어휘=3.85  매칭단어=['은행']
        → https://www.fsc.go.kr/no040101?cnId=1610  (금융위원회)
     case=C12  수법일치=1(loan_bait)  어휘=3.85  매칭단어=['직원']
        → https://www.police.go.kr/...  (경찰청 투자리딩방 사기유형)

  ▸ 단어 **한 개**('은행', '직원')로 매칭됐다.
  ▸ match_scam_cases 의 min_score=5.0 은 인자로 남아 있을 뿐 **코드에서 실제로
    쓰이지 않는다**(2026-08-05 수정 때 판정축을 '수법 카테고리 일치'로 바꾸면서
    하위호환용으로만 남김. 함수 docstring 에도 그렇게 적혀 있다).
    → 카테고리 1개 + 키워드 1개만 겹치면 무조건 근거로 붙는다. 하한선이 없다.
  ▸ C12 는 내용상 '유명인·투자리딩방 사칭' 사례다. 대출과 무관한데도 블롭에
    '인터넷대출'·'권유' 가 있어 loan_bait 로 분류돼 있었고, 공통 단어 '직원'
    하나로 대출 문장에 붙었다. 명백한 오매칭이다.

  ▸ 게이트도 통과해 버린다: loan_bait = (대출|대환|저금리…) AND (안내|상담|권유…).
    "정부지원 대출상품을 설명하고 상담을 권함" 은 정상 서술문인데도 조건을 만족한다.

 (D) 판정 결과
     risky = True (사기사례 신호가 severity=attention)
     has_confident_source = official_confident(False) or bool(matched_scam)(True) = True
     → verdict_hint = partially_matched (의심)
     즉 사기사례 매칭 1건이 '확신 있는 근거' 로 승격되는 구조다.
     8/6 에 matched_evidence(근거_검증표)는 이 승격에서 제외했지만,
     matched_scam 은 그대로 남아 있다.


5. 30건 전수 확인 - 이 문제가 얼마나 넓은가
--------------------------------------------------------------------
평가셋 30건에 대해 사기사례 매칭 근거를 전수 출력한 결과:

  · 정상(N01~N10)  : 매칭 0건        ← "정상 오판 0" 은 그대로 유지된다
  · 사칭(S)        : 8건 매칭. 대부분 2~3단어가 겹친다(S01 은 수법일치 2)
                     단어 1개 매칭은 S02('지원금') 1건뿐 - 결과는 맞아서 무해
  · 경계(B)        : B07 **한 건만** 매칭. 그리고 그 한 건이 단어 1개 매칭이다.

→ 즉 이번 오매칭은 30건 평가셋의 지표를 흔들지 않는다. 그래서 지금까지 안 보였다.
  평가 기준이 '정상 오판 0 / 사칭 검출률' 이라 **경계 케이스의 근거 품질**은
  측정 항목에 없었다. 측정 공백이 원인 발견을 늦춘 것이다.


6. 정리 - 원인 3줄
--------------------------------------------------------------------
① 금융위 카드뉴스는 임베딩(0.679)이 아니라 사기사례 코퍼스에서 왔고,
   그 코퍼스는 실질 하한선이 없어 공통 단어 1개로 근거가 붙는다.
② 그렇게 붙은 '사칭 사례' 신호가 프롬프트에 들어가 모델을 사칭 검증 프레임으로
   몰았고, 입력에 없는 은행명·명함·문자·직통번호를 지어내게 했다.
③ 가드레일은 판정어와 URL 출처만 본다. 입력에 없는 사실을 전제로 까는 문장은
   검사 항목 자체가 없어 3/3 전부 통과했다.

※ ①이 ②의 원인이다. 근거 품질을 고치면 질문 품질이 따라 올라간다.
   판단은 사용자에게 넘김. 수정은 지시 후 진행한다.
