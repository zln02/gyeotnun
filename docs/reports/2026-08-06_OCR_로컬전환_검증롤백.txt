OCR 로컬(PaddleOCR) 전환 — 구현·검증·롤백 (2026-08-06)

  결론: 전환 인프라는 구축 완료(한 줄 토글). 그러나 검증에서 사칭 신호 9/10
  (S08, 공백 누락)로 "10/10 유지" 기준 미달 → 지시대로 Vision 으로 롤백.
  정상 오판은 0(절대조건 충족). 응답 형식 불변(백엔드 단독).

1. 구현 (임베딩과 같은 구조)

- config.OCR_PROVIDER = os.getenv("OCR_PROVIDER", "local") — vision/local 토글.
  임베딩의 EMBEDDING_PROVIDER 와 동일 구조.
- services/ocr.py: extract_from_image 첫 줄에서 OCR_PROVIDER=="local"이면
  _extract_local()(PaddleOCR)로 분기. Vision 코드·키·프롬프트는 그대로 보존.
- _extract_local: bytes→ndarray 디코드→predict→말풍선 필터(in-memory PIL)→UI 잡음
  제거. ★ 원본 이미지를 디스크에 쓰지 않는다(Vision 경로와 동일 원칙).
  반환은 ExtractResult(text, detected_domain, status) — Vision 과 완전히 동일.
- 구성 = 튜닝 baseline: 모바일 검출기 + 문서 전처리 off + mkldnn on + 말풍선 필터.
  전처리 4종·box_thresh 0.4 는 넣지 않음(지시).
- 인프라: requirements.txt에 paddlepaddle 3.0.0 + paddleocr 3.7.0, Dockerfile 에
  opencv 런타임 라이브러리(libgl1 등), 모델 캐시 마운트(HOME=/app/data/paddle_home).
  .dockerignore로 data/(11GB) 제외해 이미지·빌드 축소.

2. 응답 형식 — 불변 (배포 순서 판단)

_extract_local 반환 필드가 Vision 과 동일(text/detected_domain/status)하고
detect_domain()도 그대로 적용된다. 응답 형식이 바뀌지 않으므로 프론트 배포
불필요 — 백엔드 단독 배포. (실측: 검증에서 "응답형식 유지: True")

3. 검증 — 평가셋 30 이미지 (로컬 경로)

| 항목 | 결과 | 기준 |
|---|---|---|
| 응답 형식 유지 | True | — |
| 정상 오판(정상→partially_matched) | 0건 | ★ 절대조건 0 → 충족 |
| 사칭 위험신호 검출 | 9/10 | 10/10 유지 → 미달 |
| OCR status=failed | 0건 | — |

미달 원인 — S08, 공백 하나

기대(Vision):  "건강보험료 환급 신청 nhis-refund24.com"  → 신호 있음(사칭 검출)
로컬 OCR:      "건강보험료 환급 신청nhis-refund24.com"   → 신호 없음
                                    ↑ '신청'과 URL 사이 공백 누락(정확도 0.98)

공백이 빠지면서 "신청nhis-refund24.com" 이 약한 근거에 걸려 no_official_source
신호가 억제됐다. 단 한 글자(공백) 차이지만 사칭 신호가 사라진다.
- 다른 9건 사칭은 정상 검출. 정상 10건은 오판 0.
- Vision 은 공백을 보존해 10/10. 로컬 전환 시 사칭 검출이 10→9 로 나빠진다.

4. 실사용 11건 / 홀드아웃 — OCR 무관

실사용 11건·홀드아웃은 텍스트 입력(SMS 텍스트/제시문구)이라 OCR 제공자와
무관하다(extract_from_text 경로). 방금 고친 초록 오출력 0/11(커밋 6c1d116)은
그대로 유지된다. OCR 전환은 이미지 입력 경로만 바꾼다.

5. 응답 시간·메모리 (기획서용 실측)

| | 값 |
|---|---|
| Vision 라이브 이미지(공유 경로 POST /checks 왕복) | 6.5초 (이전 기록 9.5초) |
| 로컬 OCR 웜 처리(추출만) | 0.66초/장 (Vision 대비 ~10배 빠름) |
| 로컬 최초 로드(+1장) | 9.8초(1회) |
| 로컬 상주 메모리(RSS, S01 처리 후) | 약 865MB (이전 재측정 피크 2.07GB) |
| 호스트 가용 | 약 12.9GB (여유 충분) |

→ 속도·비용(외부 호출 0)만 보면 로컬이 크게 유리하나, 정확도(사칭 검출)에서
막혀 이번엔 채택하지 않는다.

6. 전환·롤백 실측 시간

- 롤백(한 줄): OCR_PROVIDER=vision + docker compose up -d api → 6.0초 만에 복귀
  (임베딩 롤백 5초와 유사). 되돌리기가 설정 한 줄임을 실증.
- 최초 로컬 활성화는 이미지 재빌드(paddle 설치)가 1회 필요했다 — 이건 인프라
  준비이고, 제공자 전환 자체는 6초 토글이다.

7. 결정

Vision 유지(롤백 완료). 사유: 사칭 신호 10/10 유지 기준을 S08 한 건(공백 누락)에서
미달. 지시대로 "하나라도 나빠지면 즉시 Vision 으로 되돌린다"를 따랐다. 정상 오판
절대조건은 0으로 충족했으나, 사칭 검출 저하를 감수하지 않는다.

- 인프라는 남겨 둔다: OCR_PROVIDER=local 한 줄이면 재활성화된다(6초).
- 재도전하려면: 로컬 OCR 후처리에서 URL/영문 토큰 앞 공백 보존(예: 한글↔영문
  경계에 공백 삽입)만 넣으면 S08 이 회복될 여지가 있다 — 별건 코드 변경이라
  이번 범위 밖. 그 전까지는 Vision.
