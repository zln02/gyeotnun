## 1-2. ★ git shortlog 검증 — 사실상 불가능했다

지시하신 "git shortlog 로 실제 커밋과 맞는지 검증"을 시도했고, **검증이 안 되는 이유
자체가 보고할 내용**이 됐다.

```
    152  Ubuntu <ubuntu@ip-172-26-1-42.ap-northeast-2.compute.internal>
      3  taeheekim123 <104884855+taeheekim123@users.noreply.github.com>
      2  hininiii <85heejin@daum.net>
      1  zln02 <wlsdud5035@gmail.com>
```

**158 커밋 중 152 건(96%)이 서버 공용 계정 하나로 남아 있다.** 이 서버에서 작업할 때
`git config user.name` / `user.email` 이 설정돼 있지 않아서, 누가 작업했든 전부
`Ubuntu` 로 기록됐다. 그 152 건이 `web/src/styles.css`(20회), `api/services/search.py`(16회),
`web/src/pages/Home.jsx`(15회), `README.md`(15회) 등 **모든 폴더에 고르게 퍼져 있어**
누구 것인지 git 만으로는 구분할 방법이 없다. 기간도 2026-07-28 ~ 2026-08-15 전체다.

→ 조치: `docs/CONTRIBUTING.md` 에 커밋 저자 설정 안내를 넣었다. **지금부터라도 각자
자기 이름으로 커밋해야 이 검증이 다음번엔 가능해진다.**

```bash
git config user.name  "본인이름"
git config user.email "본인메일"
```

이름이 남은 3명만 검증할 수 있었고, 그중 하나가 표 2 와 어긋난다.

| 저자 | 실제로 건드린 파일 | 표 2 담당 | 판정 |
|---|---|---|---|

| `zln02` (박진영) | 최초 스켈레톤 전체 (`85b2bdf init:`) | 박진영 = API·DB·배포 | 성격상 일치 ✅ |
| **`taeheekim123` (김태희)** | **`api/services/masking.py`, `api/tests/test_masking.py`** | 김태희 = **프롬프트** (마스킹은 **박진**) | **어긋남** ⚠ |

**어긋난 1건 상세**

```
8757ed3 / 49bc214 / 31007a3  2026-08-06
  feat(masking): 개인정보 마스킹 정규식 및 검증 로직 개선 (#1)
  건드린 파일: api/services/masking.py, api/tests/test_masking.py
```

김태희가 **박진 담당 영역인 마스킹**을 고쳤다. 다만 이것을 "위반"으로 볼 필요는 없어 보인다.
기획서 표 1 에서 김태희 역할이 **"공식 근거 검증 — 기관·연도·페이지·URL"** 이고,
마스킹 정규식 검증은 그 성격(패턴을 검증해 정확도를 올리는 일)에 가깝다.
**표 2 를 김태희 쪽으로 넓히든, 이 커밋을 예외로 두든 사람이 정할 일이라 고치지 않았다.**
지금은 어긋난 사실만 적는다.

★ 나머지 3명(박진 · 장지석 · 김유리)은 **git 에 이름이 하나도 남아 있지 않아
검증 자체가 불가능하다.** "커밋이 없다"가 아니라 "누가 했는지 기록이 없다"이다.
이 둘을 혼동해서 적으면 안 된다.

**Claude 최종 의견: A 는 이번 라운드에서 3건 모두 보류를 권한다.**
확실한 것 1건을 위해 오검출 2건을 걸러 내는 비용이 크고, 2번조차 본문 확인이 필요하다.
"확실한 것부터 넣는다"는 이번 라운드 방침에 A 는 맞지 않는다.
