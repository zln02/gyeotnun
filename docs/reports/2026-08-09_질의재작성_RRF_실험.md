## 0. 정답 라벨을 3종으로 분리했습니다 (작업 1 지시 반영)

| 라벨 | 뜻 | 건수 | 성공의 정의 |
|---|---|---:|---|
| `doc` | 출처_URL 이 공식문서 인덱스의 특정 문서를 가리킴 | **20** | 그 문서를 찾아야 성공 |
| `scam` | 출처_URL 이 `SCAM_CASES` 로 이관된 경보문 | **2** | 공식문서 검색 대상이 아님(별도 신호) |

`none` 8건은 **전부 경계·기대판단 `확인불가`** 입니다(B03~B10).
작업 1에서 "실패"로 세던 B08~B10 은 이 라벨 안에 들어가고, **별도 지표
`확인불가 정확 처리`** 로 뺐습니다.

## 3. 규칙 기반 질의 재작성이 실패한 이유 (지시 2)

### 먼저 — 재사용하라고 하신 "입력 인식 단계"는 없습니다

지시서에 "이미 있는 입력 인식 단계(본문·발신자·주장·요구 행동 분리) 출력을
재사용" 하라고 되어 있어 코드를 확인했습니다. **그런 단계는 없습니다.**

| 실제로 있는 것 | 무엇을 주는가 |
|---|---|
| `ocr.detect_domain()` | 도메인 4종(public_support/health/finance/digital_literacy) |
| `search.detect_signals()` | 요구 행동 위험 신호 3종(조건 누락·재촉·연락처) |
| `scam_taxonomy.detect_categories()` | 수법 카테고리 |
| OCR Vision 프롬프트 | 말풍선 본문만 추출 — **발신자는 의도적으로 버림**(작업 A 보고) |

'주장 요지', '기관명', '제도명'을 뽑는 코드는 없어서 **이번 실험용으로 새로
만들었습니다**(`rewrite_rule`, 코퍼스에 실재하는 기관명 사전 + 제도명 접미사 규칙).
창작한 기관명·제도명은 넣지 않았습니다.

### 결과가 나쁜 이유

재작성 질의는 이렇게 생겼습니다:

```
원문 : 건강보험료 환급 신청 nhis-refund24.com
재작성: 건강보험료 환급 신청 환급금미끼 안내 신청 대상 자격 조건
```

`안내 신청 대상 자격 조건` 을 붙여 **제도 안내문 쪽으로 질의를 당겼는데**,
코퍼스에 그 문자에 대응하는 제도 안내문이 없습니다(작업 1 §3). 그래서
"신청/대상/자격/조건" 이라는 일반적인 행정 어휘와 잘 맞는 **엉뚱한 제도 문서**가
올라옵니다 — 오답 근거가 2 → 7건으로 튄 원인입니다.

정상 10건에서 10/10 → 8/10 으로 떨어진 것도 같은 이유입니다. 원문에 이미
정답 제도명이 그대로 들어 있는데, 재작성이 그걸 일반 어휘로 희석했습니다.

**교훈: 질의를 문서 장르 쪽으로 당기는 전략은, 그 장르의 문서가 코퍼스에 있을 때만 통합니다.**

## 4. LLM 재작성(D)은 측정하지 못했습니다

```
anthropic.BadRequestError: 400 - Your credit balance is too low
to access the Anthropic API.
```

★ **추정치로 채우지 않습니다.** 크레딧이 충전되면 아래 한 줄로 D 까지 포함해
재측정됩니다(실패해도 그 사실만 기록하도록 스크립트를 고쳐 뒀습니다).

```bash
docker compose exec api python3 experiments/exp_query_rewrite.py
```

다만 C 의 결과가 시사하는 바는 적어 둡니다 — **이건 예측이지 측정이 아닙니다.**
LLM 이 '주장 요지'를 더 잘 뽑더라도, 대응하는 제도 안내문이 코퍼스에 없다는
조건은 그대로입니다. 표현을 다듬는 것으로 §3 의 근본 원인이 해소되지는 않을
가능성이 높습니다.

## 5. 오답 근거 지표에 대한 정직한 부기

`오답 근거 제시` 는 **`doc` 라벨 20건에 한해** "근거를 붙였는데 정답이 하나도
없는 경우"만 셌습니다. 그 밖에 이런 것도 있습니다:

- `none` 라벨 8건 중 **5건(B03~B07)은 참고자료를 붙입니다.** 정답 라벨상으로는
  "붙이지 않는 게 맞는" 케이스입니다.
- 다만 이 5건의 **판정은 전부 `no_source_found`(확인불가)로 정확합니다.**
  참고자료로 보여 주되 확신하지 않는 설계(`EMBEDDING_MIN_SCORE` 와
  `CONFIDENT_MATCH_THRESHOLD` 분리)가 의도대로 동작한 결과입니다.
- 즉 **사용자에게 거짓을 말하지는 않습니다.** 그래서 이 5건을 "오답 근거"에
  합산하지 않았고, 대신 여기 적어 둡니다. 작업 5의 신규 케이스에는
  이 구분을 라벨 단계에서 넣겠습니다.
