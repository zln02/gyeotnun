## 1-1. `search.py` — 686줄, 책임 5가지

| # | 책임 | 위치 |
|---|---|---|
| ① | 검색 (BM25·임베딩·RRF·웹) | `search_corpus` `match_official_docs_hybrid` `match_official_docs_safe` |
| ② | **위험행동 탐지** | `detect_risk_action_detail` `detect_risk_action` |
| ③ | **신호 조립 + 인용문 생성** | `detect_signals` `risk_action_quote` `collect_evidence` |
| ④ | **폴백률 관측** | `_observe_search_fallback` |
| ⑤ | 판정 힌트 결정 | `collect_evidence` 후반 |

**실제 문제는 "줄 수"가 아니다.** ②는 검색을 전혀 쓰지 않는다 — 문장만 본다.
`detect_risk_action_detail` 은 `text` 하나만 받고 코퍼스·임베딩·BM25 어느 것도
건드리지 않는다. 그런데 이 함수를 고치려면 검색 모듈을 열어야 하고, 검색 임계값을
고치려면 위험행동 어휘 사전을 지나쳐야 한다. **8/13 작업에서 실제로 겪은 비용이다.**

그리고 이 함수는 지금 **두 곳에서 쓰인다** — `urgency_pressure` 강등 게이트(옛 용도)와
화면 신호(새 용도). 용도가 둘인데 반환 계약은 하나다. 유형이 틀려도 무해하던 시절의
함수가 지금은 유형이 틀리면 화면이 거짓말을 한다.

다만 **그것을 자동으로 돌리는 것이 아무것도 없다.** 사람이 기억해서 손으로 돌려야 한다.

이건 성능 문제가 아니다. 이 프로젝트가 스스로에게 건 규칙 —
**"측정하지 않은 것을 측정한 것처럼 쓰지 마라"** — 을 우리 문서가 어긴 상태다.

## 2-4. 테스트가 운영 DB 에 행을 넣는 문제 — 실측으로 확인·정량화

**방금 이 감사에서 pytest 1회 실행이 운영 DB `error_logs` 에 5행을 넣었다** (실측):

```
최근 15분: EX-003 3행, GN-001 2행
```

누적:

| 코드 | 누적 행 | 마지막 |
|---|---|---|
| `GN-001` | **150** | 2026-08-14 10:14 |
| `EX-003` | **135** | 2026-08-14 10:14 |
| `GN-002` | 3 | 08-09 |
| `EX-001` | 2 | 08-06 |
| `ST-001`·`IN-002`·`GN-003` | 각 1 | — |

**`GET /errors/summary` 가 지금 사실이 아닌 수치를 반환한다.** 상위 2개 코드 285행의
대부분이 테스트가 만든 것이고, 그중 GN-001·EX-003 은 정확히 **폴백을 모킹하는 테스트**가

## 3-1. 미해결 목록 대조 — 실측 결과

8/6 리뷰가 추적하던 **17개 항목**을 현재 코드·운영 설정·라이브 응답에 하나씩 대조했다.

| | 건수 |
|---|---|
| **완전 해소** | **2건** (라이브·운영 설정 실측으로 확인) |
| **부분 해소** | **2건** (핵심은 막혔고 잔가지가 남았다) |

**해소된 2건은 이름을 밝혀도 공격 표면이 아니라서 여기 적는다.**

| 항목 | 근거 (실측) |
|---|---|
| **마스킹 전 원본 이미지의 외부 전송** | 운영 컨테이너 실측 **`OCR_PROVIDER = local`**. `ocr.py:261` 이 PaddleOCR 오프라인 경로를 탄다. **이미지가 외부로 나가지 않는다** — 8/6 당시 "높음·정책 결정 필요"였던 항목이 로컬 OCR 프로덕션 승격으로 닫혔다 |
| **프로덕션 `--reload`** | `docker-compose.yml:52` 운영 command 에서 제거됨 (`--workers 1` 은 그대로) |

부분 해소 2건과 잔존 13건의 **위치·재현·수정안은 공개 저장소에 적지 않는다.**
`docs/security/internal/audit_2026-08-14.md` 를 볼 것. 성격만 적으면:

- 부분 해소 하나는 **집계 엔드포인트 접근 통제**다 — 두 집계는 운영자 게이트로 닫혔고
  (라이브 404 확인), **같은 지적에 함께 묶여 있던 정적 응답 하나가 열린 채 남았다.**
  의도적 결정이고 코드에 근거가 적혀 있으나, 원 지적이 문제 삼은 필드가 그 응답에 그대로 있다.
- 부분 해소 다른 하나는 **의존성 계열**이다. 직접 지정 패키지는 올렸고,
  FastAPI 핀에 막힌 전이 의존성이 남았다(§3-3의 starlette 과 같은 건).
- 잔존 중 **높음은 1건** — 앱 계층 비용 상한이다. 네트워크 계층(nginx `limit_req`)에서
  부분 완화돼 있고 앱 계층은 여전히 없다. 8/6 판정 "부분 조치"가 그대로다.
- `device_id` 위조 가능성은 **그대로다.** 코드가 스스로 한계를 명시하고 있고
  (`routers/checks.py:37`), 8/6 이후 이 부분은 바뀌지 않았다.
- `mock=1` 우선순위: 로직은 `bool(mock) or DEMO_FALLBACK_TO_MOCK` 그대로다.
  **운영 실측값 `DEMO_FALLBACK_TO_MOCK = False`** — 자동 mock 폴백은 꺼져 있다.
  즉 지금 운영에서는 `?mock=1` 을 명시할 때만 목업이 나간다.

## 3-2. ★ 신규 기능 점검 — 인젝션 · XSS

이번에 새로 만든 경로는 **사용자 입력 → 위험행동 탐지 → 인용 구절 → 화면**이다.
네 지점을 각각 봤다.

| 점검 | 결과 | 근거 |
|---|---|---|
| **인용문에 원문 개인정보가 실릴 수 있는가** | **없다** | `routers/checks.py:163` 이 `stored["masked_text"]` 를 넘긴다. 원문은 애초에 저장되지 않는다 |
| **사용자 입력이 정규식으로 컴파일되는가** | **없다** | `search.py` 의 정규식은 2개뿐이고 둘 다 리터럴(`_ORG_SUFFIX_RE`, 문장 분리 패턴). 탐지는 전부 `in` 부분문자열 비교 |

| **인용문이 화면에서 XSS 가 되는가** | **되지 않는다** | `Judgment.jsx:62` 가 JSX 텍스트 보간(`{...}`)이라 React 가 자동 이스케이프한다. `web/src` 전체에서 `dangerouslySetInnerHTML` · `innerHTML` · `eval(` **0건** |

부가로 `_RISK_QUOTE_MAX = 60` 이 인용 길이를 자르므로 응답 크기가 입력에 비례해
커지지도 않는다. **신규 기능은 보안 관점에서 깨끗하다.**

그건 8/6 리뷰의 기존 항목이고 이번 작업이 만든 것이 아니다.

| **CPU 피크** | **여기가 제약이다.** 확인 1건이 순간 2코어 이상을 먹는다. **4 vCPU 에서 동시 확인 2건이면 포화**하고, 그 위에 다른 프로젝트가 얹히면 서로 밀어낸다 |

**결론: 상시 자원(메모리·디스크)은 여유가 크고, 순간 CPU 만 좁다.**
동시 서빙 상대가 CPU 를 지속적으로 쓰는 성격(다른 로컬 모델 추론 등)이면 충돌하고,
I/O·메모리 위주면 무난하다. 얹기 전에 **빌드 캐시 정리부터** 하는 것이 순서다.
