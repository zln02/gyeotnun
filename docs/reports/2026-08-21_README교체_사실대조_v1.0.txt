2. ★★ 대표 사례 사실 대조 — 어긋난 것 5건
==========================================

  말씀하신 대로 기억 오차가 있었습니다. 유형도 지난번과 같습니다 —
  **방향은 맞는데 배율이 다른** 형태입니다.

  [2-1] 사례1 — "평가셋이 30건뿐이라 1건이 3.3%p"     ★ 수정함

      30건 세트 자체로는 1건 = 3.33%p 가 맞습니다. 그런데 바로 앞에 인용한
      **95.5% 의 모수는 22건**입니다(음성 8건 제외, 21/22).
      같은 문단에서 분모가 두 개 섞였습니다.

          → "그 수치의 모수는 22건이라 1건이 4.5%p" 로 고쳤습니다.

      나머지는 전부 일치했습니다: 95.5%(21/22) · 71.4%(80/112) ·
      70.0%(21/30) · 1.4%p 차이. 근거 기준선_확대평가셋_2026-08-11.md §35.

  [2-2] 사례3 — **"방어가 30% 약해집니다"**            ★★ 가장 크게 어긋남

      "가중치가 30% 안팎 오른다" 는 **맞습니다** (log(N+1) 비 51→185 = 1.323).
      틀린 것은 그다음 문장입니다.

      실측(IDF척도이동_A안_2026-08-12.md §2)이 말하는 것은 세 가지입니다.

        ① 정상 오판 0 을 유지하는 최소 min_score 는
             N= 51  확대 6.75  홀드 11.00
             N= 80       13.75       12.25   ← 2.04배 뜀
             N=185       14.75       13.50
           **로그를 따르지 않고 계단으로 뜁니다.** 30% 가 아닙니다.

        ② 그런데 **5.0 에서의 실제 오판은 N 과 무관하게 1건으로 불변**입니다.
           즉 "방어가 30% 약해진다"가 아니라 **"당장 오판은 안 늘고
           안전 여유가 6.75 → 14.75 로 깎인다"** 가 정확합니다.

        ③ 그리고 **N=51 인 지금도 5.0 은 이미 부족합니다** — 정상 오판이
           이미 1건 나고 있습니다. 초안에 이 사실이 빠져 있었습니다.

      ★ 초안의 문서 링크 설명에는 "재교정 곡선(로그가 아니라 계단)" 이라고
        적혀 있었습니다. **링크 설명이 본문보다 정확했습니다.**
        본문을 링크 설명에 맞춰 고치고, 곡선 표를 본문에 넣었습니다.

  [2-3] 작업 원칙 — "공개 수치 20ms → 자체 실측 141.5ms (7.1배)"   ★ 근거 없음

      **저장소 어디에서도 20ms · 141.5ms · 7.1배를 찾지 못했습니다.**
      local_embeddings_report.md 의 응답시간 열은 Upstage 112ms /
      bge-m3 558ms / bge-m3-ko 572ms 이고, 최종 채택한 e5-small-ko-v2 의
      질의 지연은 그 표에 없습니다.

      제가 오늘 직접 재 봤습니다(운영 컨테이너, n=15):
          평균 223.6ms · 중앙값 185.2ms · 범위 86.6~710.5ms
      141.5ms 와 맞지 않고, 다른 부하와 섞인 값이라 이것도 README 에
      넣을 만한 수치가 아니라고 판단했습니다.

      → "실측하지 않은 값을 README 에 넣지 마라" 는 지시에 따라,
        **근거가 있는 계기로 교체**했습니다:
        "상용 임베딩 112ms vs 로컬 후보 558ms — 공개 인상과 실측이 달랐다"

      ★ 141.5ms 의 출처를 알고 계시면 알려 주십시오. 근거 문서가 있으면
        원래 문장으로 되돌리는 게 더 강합니다(7.1배가 훨씬 인상적입니다).

  [2-4] 작업 원칙 — "실패 시험이 SPA 폴백 때문에 200을 받아 통과"  ★ 방향이 반대

      저장소에 있는 실물은 이렇습니다(security/review_2026-08.md §52).

          보안 스캔이 "/docs 가 공개된다"고 경고했는데, nginx 가 /api/ 와
          /health 만 프록시하므로 /docs 는 **SPA(index.html)로 폴백돼 200**
          이 나온 것이었다. → **오탐**.

      즉 "검사가 잘못 통과" 가 아니라 **"검사가 없는 취약점을 걸었다"** 입니다.
      원칙("실패해야 할 검사가 실제로 실패하는지 확인한다")은 저장소 전체가
      지키고 있으므로 유지하고, 계기만 실물대로 고쳤습니다.

  [2-5] 헤더 — "2026년 8월부터 **무중단** 운영 중"                ★ 성립 안 함

      백엔드 배포는 deploy/verify_restart_race.sh 가 하고, 그 안에
      `docker compose restart api` 가 있습니다(122행). 최근 이틀에만

      ★ 재시작 직후 경합 검사를 배포 절차에 넣어 둔 것이 이 프로젝트의
        강점인데, "무중단"이라고 쓰면 그 절차와 정면으로 모순됩니다.
