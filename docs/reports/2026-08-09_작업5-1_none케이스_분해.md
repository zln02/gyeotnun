# 작업 5-① — `none`(근거 없음이 정답) 8건 분해 (2026-08-09)

- 스크립트: `api/experiments/diag_none_cases.py` (측정만, 임계값 무변경)
- 원자료: `api/data/diag_none_cases.json`
- 임계: 표시 하한 `EMBEDDING_MIN_SCORE=0.6155` / 확신 `CONFIDENT=0.6790`

## 결론 먼저

> **"잘못된 근거 제시"는 이 8건에서 0건입니다.**
> 근거를 붙인 5건은 전부 **표시 하한과 확신 임계 사이**(0.6290~0.6760)의
> 주제상 인접한 문서였고, **확신 임계를 넘겨 노출한 건 하나도 없습니다.**
>
> 대신 **다른 결함이 1건 나왔습니다 — B06 이 `의심`으로 올라갑니다.**
> 원인은 근거가 아니라 **`urgency_pressure` 신호 오탐**입니다.

## 2. "붙은 근거가 오답인가" — 케이스별로 따져 봤습니다

지시하신 "오답 근거를 붙였는지"에 답하려면 **붙은 문서가 주제상 맞는지**를
개별로 봐야 합니다. 뭉뚱그려 "관련 있다"고 쓰지 않고 나눠 적습니다.

| ID | 입력 주제 | 붙은 문서 | 판정 |
|---|---|---|---|
| B04 | 기초연금 신청 조건 | **기초연금** | **정확히 같은 제도** |
| B05 | 건강보험공단 검진 안내 | 의료급여수급권자 건강검진비 지원 | 같은 영역(건강검진), 제도는 다름 |
| B06 | 에너지 지원금 포스터 | **에너지바우처** / 긴급복지 연료비 | **정확히 같은 영역** |
| B07 | 정부지원 대출상품 | 소상공인지원(융자) | 같은 영역(정부지원 융자), 대상은 다름 |
| B03 | "복지 담당자가 지원 대상일 수 있다고 안내" | 긴급복지 장제비지원 / 교육지원 | **느슨함.** 입력이 어떤 제도인지 말하지 않아 지목할 정답 자체가 없음 |

- **명백한 오답(주제가 어긋난 문서)은 없습니다.** B03 이 가장 느슨하지만,
  입력 자체가 "어떤 지원인지" 말하지 않아 **맞출 정답이 존재하지 않는** 케이스입니다.
- 5건 전부 **"참고자료로 보여 주되 확인됨으로 단정하지 않는"** 구간에 있습니다.
  표시(0.6155)와 확신(0.6790)을 분리한 설계가 **의도대로 동작했습니다.**

## 3. ★ 실제 결함 1건 — B06 이 '의심'으로 올라간다

```
입력  : 복지관 게시판의 에너지 지원금 포스터. 기관 로고는 있으나 신청 마감일이 지나 있음.
기대  : 확인불가
실제  : 의심(partially_matched)
```

신호를 실측했습니다.

```
attention  urgency_pressure     서두르게 만드는 표현이 있습니다…
info       official_source_found  에너지바우처
info       official_source_found  긴급복지 연료비 및 전기요금
```

### 원인은 근거가 아니라 신호입니다

- 붙은 근거의 최고 점수는 **0.6760 < 확신 임계 0.6790** → `official_confident=False`.
  **근거 때문에 올라간 게 아닙니다.**
- `search.py` 의 3단계 판정은 `risky = any(severity == "attention")` 이면
  `partially_matched` 로 올립니다. 여기서 `urgency_pressure` 하나가 `risky` 를 켰습니다.
- 그런데 이 문장의 "**신청 마감일이 지나 있음**"은 **재촉이 아니라 서술**입니다.
  이미 지난 마감일을 설명하는 문장인데 "서두르게 만드는 표현"으로 잡혔습니다.
  → **`urgency_pressure` 규칙의 오탐**입니다.

### 고치지 않았습니다 — 이유

`detect_signals` / `SIGNAL_RULES` 를 손대면 **사칭 10건 위험신호 검출 10/10**
절대조건에 직접 영향이 갑니다(사칭 케이스 상당수가 `urgency_pressure` 로 잡힙니다).
지금은 **기록만** 남기고, 고칠 경우 30건·홀드아웃 5건 재측정을 선행 조건으로
두겠습니다. 판단을 주시면 진행하겠습니다.

참고로 이 1건은 **안전한 방향의 오류**입니다(확인불가 → 의심, 더 조심하는 쪽).
반대 방향(의심 → 확인됨)이었다면 즉시 고쳐야 할 사안입니다.

## 4. 이 분해가 지표에 주는 함의

기존 "근거 검색 성공률"만 보면 B03~B07 은 **성공**으로, B08~B10 은 **실패**로
잡힙니다. 실제로는 **정반대에 가깝습니다** — B08~B10 이 가장 깨끗하게 처리된
케이스입니다.

| 지표 | 이 8건에서의 값 |
|---|---|
| (기존) 근거 검색 성공률 | 5/8 = 62.5% — **의미 없음** |
| **확인불가 정확 처리율** (판정 기준) | **7/8 = 87.5%** |
| **근거 미부착률** (가장 엄격) | 3/8 = 37.5% |
| **★ 잘못된 근거 제시율** | **0/8 = 0%** |

→ 작업 5 신규 40건은 처음부터 `doc`/`scam`/`none` 으로 라벨링하고,
   `none` 케이스는 **"확인불가 정확 처리"** 로만 채점합니다.
   `근거 검색 성공률`은 `doc` 라벨에서만 셉니다.
