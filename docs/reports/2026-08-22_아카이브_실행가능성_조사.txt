1. LICENSE 부재 — 현황과 선택지
================================

  [1-1] 현황

      저장소에 LICENSE 파일 없음.
      GitHub API 응답:  "licenseInfo": null
      → 법적으로 **저작권자 전부 보유(All rights reserved)** 상태입니다.
        공개돼 있어도 제3자는 복제·수정·재배포 권리가 없습니다.
        "공개 저장소니까 써도 된다" 는 성립하지 않습니다.

      ★ 6인 공동 저작물입니다. 저작권법상 공동저작물의 이용 허락은
        **저작자 전원 합의**가 원칙입니다. CLI 가 정할 수 있는 사안이 아닙니다.

  [1-2] 세 줄 비교 — 이 프로젝트 맥락에서

      MIT
        가장 짧고 널리 읽힙니다. 조건은 "저작권 표시와 라이선스 전문을 유지" 하나뿐.
        특허에 대해 아무 말을 하지 않습니다.
        → 포트폴리오 목적(읽히고 인용되는 것)에는 이걸로 충분합니다.

      Apache-2.0
        MIT 조건에 더해 **특허 실시권을 명시적으로 부여**하고, 특허 소송을 걸면
        그 권리가 소멸하는 조항이 있습니다. 변경 사항 고지 의무도 있습니다.
        → 이 저장소가 쓰는 모델 두 개가 이미 Apache-2.0 입니다
          (e5-small-ko-v2 · PaddleOCR). 같은 라이선스로 맞추면 조합이 단순해집니다.

      그 외 (GPL 계열 · CC 계열)
        GPL 계열은 파생물까지 같은 라이선스를 요구해 채용 포트폴리오에는 과합니다.
        CC 계열은 **소프트웨어에 권장되지 않습니다**(CC 재단 자체 권고).
        → 코드에는 권하지 않습니다.

  [1-3] ★★ 코드 라이선스가 코퍼스·모델까지 덮지 않습니다

      이게 이 저장소에서 가장 중요한 점입니다.

        코드(api/ · web/ · deploy/ · tools/)   ← LICENSE 가 정하는 범위
        모델 가중치                            ← 각 모델의 라이선스
                                                 e5-small-ko-v2 · PaddleOCR = Apache-2.0
                                                 (저장소에 포함돼 있지 않고 실행 시 내려받음)
        코퍼스(공공기관 원문)                  ← **기관별로 다 다름** (아래)
        평가셋 CSV(팀 자작)                    ← LICENSE 범위이되, 별도 명시 권장

      코퍼스 라이선스 실측 (records_merged.jsonl 1,024건)

          377건  이용허락범위 제한 없음          ← 유일하게 명확

        판단은 이 실측에 근거한 것이고, 타당합니다.

  [1-4] 제안 (사람이 정합니다)

      LICENSE 파일 하나로 끝내지 말고 **세 줄을 함께** 두는 것을 권합니다.
