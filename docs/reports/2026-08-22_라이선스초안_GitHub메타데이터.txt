1. 샘플 코퍼스 기각 — 실험 기록으로 남겼습니다
==============================================

  docs/evaluation/샘플코퍼스_기각_2026-08-22.md

  지시하신 문장을 문서의 결론부에 그대로 살렸습니다.

      "문서 35% 로 근거는 88% 유지되나 확신 오답이 0→2건"

  그리고 그것이 무엇의 실증인지 한 줄로 못박았습니다.

      ★ 코퍼스를 줄이면 근거를 덜 찾는 것이 아니라,
        **틀린 근거를 확신과 함께 내밀기 시작한다.**

      근거 붙는 비율만 봤다면 "88%나 되는데 충분하다"고 결론냈을 것이다.
      안전 지표를 따로 세지 않았으면 못 봤다.

  ★ 규칙으로 승격해 적었습니다 — "코퍼스 규모를 바꾸는 변경은 '근거를 몇 건
    찾는가' 만으로 판단하지 않는다. 확신 오답 근거를 함께 세고, 0건이 아니면
    채택하지 않는다."
    ★ 반대 방향도 적었습니다: **늘리는 쪽은 안전할 것이라고 가정해 왔는데,
      그 가정을 확인한 적이 없습니다.**

  확신 판정을 끄는 안도 기각 사유와 함께 기록했습니다("실제와 다르게 도는
  데모가 되기 때문"). 지시 문장 그대로입니다.

5. ★ 4번을 위한 사전 조사 — mock 3줄이 실제로 도는가
====================================================

  README v2 전문이 없어 교체는 못 했지만, 검증은 미리 해 뒀습니다.

  [5-1] 새로 클론한 환경에서 mock 전체 플로우 — **돕니다**

      /home/ubuntu/gyeotnun 을 새로 clone 한 뒤 별도 venv 에서 확인:

          /health                    → 200
          POST /checks?mock=1        → 200  check_id=chk_demo
          GET  evidence?mock=1       → 200  references 3건
          POST dialogue?mock=1       → 200  질문 정상 (고정 응답)

      ★ .env 는 .env.example 을 복사만 했고 **키는 전부 비어 있습니다.**
        `?mock=1` 은 `use_mock()` 이 `bool(mock) or DEMO_FALLBACK_TO_MOCK` 이라
        환경변수 없이도 동작합니다.

  [5-2] ★★ 그런데 requirements.txt 전체를 설치할 필요가 없습니다

      위 검증은 **10개 패키지만** 설치하고 돌렸습니다.

          fastapi · uvicorn[standard] · pydantic · python-multipart ·
          SQLAlchemy · httpx · python-dotenv · rank-bm25 · numpy · anthropic

      빠진 것: torch(1.1GB) · sentence-transformers · paddlepaddle ·
                paddleocr · psycopg2-binary · pytest

      확인한 이유: torch·paddle 이 전부 **지연 import** 라 앱 기동에 필요하지
      않습니다. DB 도 기본값이 sqlite 라 psycopg2 가 필요 없습니다.

      → 지금 requirements.txt 로 "빠르게 돌려보기" 를 시키면 **torch 1.1GB 를
        받게 됩니다.** 빠르지 않습니다.

      제안: api/requirements-mock.txt 를 두고 "빠르게 돌려보기" 는 그걸 쓴다.
            전체 기능(실제 검색·OCR)이 필요할 때만 requirements.txt.
            ★ 채택하시면 만들겠습니다. 지금은 제안만입니다.

  [5-3] python-multipart 고정 — 값까지 확인했습니다

      현재:  python-multipart>=0.0.31
      실측:  방금 설치된 버전 **0.0.32**

      → `python-multipart==0.0.32` 로 고정하는 것을 제안합니다.
