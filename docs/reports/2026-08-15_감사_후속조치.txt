2. 자동 회귀 검사 — 서버 cron  [커밋 faad0f1]
---------------------------------------------
문제
  하한선_결정_2026-08-13.md 와 IDF척도이동_A안_2026-08-12.md 가 "CI 가 기준선을
  지킨다"를 전제로 min_score=5.0 유지를 결정했는데, 그 CI 가 실재하지 않았다.
  결정이 성립하지 않는 전제 위에 서 있었다.

GitHub Actions 를 쓰지 않은 이유 (지시대로)
  - 검색 코퍼스가 저장소에 없어 호스트 러너에서는 회귀 테스트가 전부 스킵된다.
    아무것도 검사하지 않은 채 항상 초록불이 된다.
  - 공개 저장소 + 셀프호스트 러너는 보안 사고 경로다.

조치
  api/tools/regression_check.py 신설
  crontab 등록:
    0 5 * * * cd /home/ubuntu/gyeotnun && sudo docker compose exec -T api \
              python -m tools.regression_check >> /home/ubuntu/gyeotnun/deploy/regression.log 2>&1

  ★ 스킵도 실패로 센다. 코퍼스가 마운트되지 않으면 테스트는 실패가 아니라 스킵이고,
    스킵은 초록불처럼 보인다. 아무것도 검사하지 않은 초록불이 가장 위험하다.
  ★ 통과/실패만이 아니라 실측한 숫자 자체를 남긴다. "언제부터 늘었나"를 로그만
    보고 되짚을 수 있어야 한다.
  ★ 실패 줄은 grep '\[regression\] FAIL' 로 찾는다.
  ★ 운영 DB 에는 쓰지 않는다 (1번의 SQLite 분리 위에서 돈다).

실측 (cron 명령줄 그대로 실행)
