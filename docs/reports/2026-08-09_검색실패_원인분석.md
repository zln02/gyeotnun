## 2. ★ 청킹은 원인이 아닙니다 (c) 0건

지시서에 "청킹 문제가 나오면 청크 크기/오버랩 변형도 함께" 라고 되어 있어 먼저 확인했습니다.

판정 방법: 정답 문서를 **쪼개지 않고 통째로** 임베딩해 유사도를 재고, 색인된 청크
최고점과 비교했습니다. 청킹이 원인이라면 *전문은 임계를 넘는데 청크는 못 넘어야* 합니다.

```
S02  최고청크 0.4880  vs  문서 전문 0.4453   (전문이 더 낮다)
S07  최고청크 0.4416  vs  문서 전문 0.4148   (전문이 더 낮다)
S08  최고청크 0.4353  vs  문서 전문 0.4357   (거의 같다)
```

**세 건 모두 전문 점수도 임계(0.6155)에 한참 못 미칩니다.** 오히려 청킹이 점수를
*올려* 주고 있습니다(짧은 조각이 주제어 밀도가 높아서). 청크 크기·오버랩을 바꿔도
0.44 → 0.62 로 갈 수 없습니다.

→ **작업 2에서 청킹 변형 실험은 하지 않습니다.** 근거가 없는 실험입니다.

## 4. 개선 여지가 실제로 있는 지점

측정에서 나온 것만 적습니다. 추정은 §5 에 따로 둡니다.

1. **S03 유형(설계상 이관)** — 정답 근거가 `SCAM_CASES` 에 있는데 사용자에게는
   "공식 자료 없음"으로 보입니다. 사기사례 매칭은 별도 신호(`similar_scam_case`)로
   이미 동작하므로, **지표 정의**를 "공식문서 근거"와 "사기사례 근거"로 나누면
   같은 시스템이 더 정확하게 평가됩니다(작업 5의 지표 세분화와 맞물립니다).
2. **B08~B10(포털 홈)** — 정답 라벨이 문서가 아니라 사이트입니다. 평가셋 라벨을
   "문서 없음(확인불가가 정답)"으로 명시하면 실패로 세지 않게 됩니다.
   ★ 이것은 **수치를 좋게 만들려는 기준 변경이 아니라 라벨 오류 정정**입니다.
   판단은 팀에 맡기고, 이 리포트에서는 **양쪽 수치를 모두** 적습니다.

| 기준 | 성공률 |
|---|---|
| 지금 기준 (30건 전부) | **23/30 = 76.7%** |
| B08~B10 을 '문서 없음이 정답'으로 제외 | **23/27 = 85.2%** |

3. **S02/S07/S08** — 남는 진짜 과제입니다. 코퍼스에 *사기 문자 원문에 가까운
   텍스트*(경보문 본문·사례 예시)가 더 들어와야 붙습니다. 검색 방식 변경보다
   **코퍼스 성격**의 문제입니다.
