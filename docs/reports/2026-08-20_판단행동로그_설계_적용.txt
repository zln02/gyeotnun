2. ★ 지시서와 실물이 어긋난 세 곳 — 실물을 따랐습니다
======================================================

  [2-1] input_type: photo / link / **voice**

    실제 입력 경로는 image · link · text 입니다.

      image → photo   이름만 맞춰 저장
      link  → link
      text  → ★ 지시서에 없었지만 **넣었습니다.** 붙여넣기는 실제로 가장 많이
              쓰이는 경로라, 빼면 대부분의 세션이 input_type=NULL 로 남습니다.
      voice → ★ **지금 API 에 음성 입력 경로가 없습니다.** 값만 열어 뒀고
              오늘 기준으로 한 건도 쌓이지 않습니다.
              (평가셋 CSV 의 '입력채널=음성' 은 평가용 라벨이지 API 경로가 아닙니다.)

  [2-2] decision: 신청 / **공유** / 보류 / 안함

    기존 값은 apply · not_apply · hold · ask_family 입니다.

      신청 = apply       보류 = hold       안함 = not_apply      (그대로 대응)
      공유 = share       ★ 지금 화면에 '공유' 버튼이 없습니다. 값만 열어 뒀습니다.

    ★★ ask_family(가족에게 물어보기)를 '공유'로 접지 않았습니다.
       가족에게 묻는 것과 남에게 퍼뜨리는 것은 **정반대 행동**입니다.
       하나로 세면 전파 위험 지표가 통째로 뒤집힙니다.

  [2-3] session_type: baseline / training / posttest

    서비스에 이 구분 자체가 없습니다. **클라이언트가 보내야만** 값이 생깁니다.
    ★ 서버가 기본값으로 baseline 을 채우지 않았습니다 — 안 보낸 것을 baseline 으로
      세면 "훈련 후에 좋아졌다"는 방향으로 데이터가 오염됩니다.


3. ★★ NULL 은 '아니오'가 아니라 '측정하지 않음'입니다
======================================================

  checked_* 4종과 question_opened 를 **nullable** 로 만들었습니다.
  클라이언트가 보고하지 않으면 False(=확인 안 함)가 아니라 NULL 입니다.

  ★ 왜 이게 중요한가: 프론트가 아직 안 붙은 오늘, 보고 없는 것을 False 로 저장하면
    **"아무도 출처를 확인하지 않았다"** 는 수치가 그럴듯하게 만들어집니다.
    측정하지 않은 것을 측정한 것처럼 만들지 않는다는 원칙이 그대로 적용되는 자리입니다.

  check_count 도 마찬가지로, 넷 다 미보고면 0이 아니라 NULL 입니다.

  집계는 NULL 을 표본에서 뺍니다. 그리고 **모든 비율에 표본 수를 함께** 돌려줍니다 —
  "3명 중 1명"과 "300명 중 100명"이 똑같이 0.333 으로 보이지 않도록.

  [3-2] question_opened 를 어떻게 재는가 — 한계를 적습니다

    "화면에 떴다"와 "사람이 열어서 읽었다"는 다릅니다.

      1) 클라이언트가 question_opened 를 보내면 그 값을 씁니다 (가장 정확)
      2) 없으면 **답을 했는지(user_reply)** 로 대체합니다

    ★ 2번의 한계: **열어서 읽었지만 답하지 않고 바로 결정한 경우를 못 잡습니다.**
      그 경우 NULL 로 남지 False 가 되지는 않습니다. 정확한 값이 필요하면
      프론트가 1번을 보내야 합니다.


4. ★ 구현 중 잡힌 것 두 건

  [4-1] 계측이 서비스를 죽일 수 있었습니다 (테스트가 잡음)

    커넥션 풀이 마르거나 엔진이 깨지면 **세션을 만드는 그 줄에서** 예외가 나고,

    test_recording_failure_never_raises 가 잡았고, 세션 획득까지 감싸는
    컨텍스트 매니저로 고쳤습니다.

5. 개인정보
===========

  ★ **자유 텍스트 컬럼이 하나도 없습니다.** 문자열 컬럼 8개는 전부 해시·UUID·
    짧은 코드값이고, 각각 최대 길이가 시험으로 고정돼 있습니다.

  ★ 허용 목록 밖의 값은 **잘라 넣지 않고 버립니다.**
    자르면 자유 텍스트의 앞부분이 그대로 남습니다
    ("어머니 통장 비밀번호가…" → "어머니 통장 비").
    events 의 target 은 길이만 잘랐지만, 이 표는 값의 종류가 미리 정해져 있어
    더 강하게 막을 수 있습니다.

  ★ user_ref = sha256(device_id) 이고 **check_store 와 같은 값**입니다.
    다른 해시를 쓰면 같은 사람이 표마다 다른 사람으로 세어집니다.

  ★ 보관 90일(purge 대상 추가) · 삭제는 delete_rows.py 로만(허용 표 추가).

  실제로 원문이 새지 않는지 시험으로 확인했습니다 —
  "어머니께 010-1234-5678 로 전화가 왔는데 통장 비밀번호를 물어봤어요" 를
  input_type·session_type·decision·card_result 에 넣어 보고, 표 전체를 훑어
  '어머니'·'010-'·'비밀번호' 조각이 **어디에도 없음**을 확인했습니다.

      채워짐   session_id(대체) · user_ref · input_type · questions_shown ·
               decision · time_to_decision · misjudge_tag · created_at
      NULL     session_type · checked_* 4종 · check_count · card_id · card_result
               question_opened (답을 한 경우만 True)

  ★ 즉 **이 표의 핵심 지표 절반이 프론트 연동에 달려 있습니다.**
    보내야 할 필드는 docs/판단행동로그_설계_2026-08-20.md 8절에 표로 정리했습니다.
    프론트 세션과 폴더를 공유하므로 web/ 은 건드리지 않았습니다.

  ★ 그리고 아직 **아무 데이터도 없습니다.** 지금 요약을 열면 total_sessions=0 입니다.
    수치를 말할 수 있게 되는 것은 실사용이 쌓인 뒤입니다.
