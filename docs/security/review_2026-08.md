# 곁눈(Gyeotnun) 보안 리뷰 — 2026-08 (공개본)

- 리뷰 범위: `api/`(FastAPI 백엔드), `web/src/`(프론트), `deploy/`(nginx·compose), 코퍼스 로딩 경로
- 방식: **읽기 전용 코드 정독**. 프로덕션에 요청을 보내지 않았고, 코드를 수정하지 않았다.
- "재현" 항목은 코드에서 확인한 것과 실행으로 확인하지 못한 것을 구분해 표기했다.

> **미해결 항목(미조치·남은 과제·본선 예정)은 라이브 서비스의 공격 표면을 드러낼 수 있어 이 공개 저장소에 두지 않고 별도로 관리한다.**
> 이 문서에는 **조치가 완료된 항목**과 **점검 결과(양호·이상 없음)**만 남긴다.

자동 취약점 점검(pip-audit·bandit·semgrep·gitleaks·npm audit)의 전체 결과와 도달 가능성 판정은 [`vulnerability_scan.md`](vulnerability_scan.md) 참고.

## 1. 조치 완료

### 1-1. 요청 빈도 제한(rate limit) · DoS 방어 — 적용·검증 완료 (2026-08-06)

nginx 설정만으로(코드·의존성 미변경) 무제한 상태를 제거했다.

- `limit_req_zone` **2개로 분리** — 비용이 드는 AI 호출 경로(`/api/v1/checks`, `/checks/{id}/dialogue`, `/checks/{id}/verdict`)는 `60r/m + burst 30`, 그 외 API는 `20r/s + burst 100`.
  > 왜 나눴나: `/api/` 전체에 같은 값을 걸면 **계측(`POST /events`)이 먼저 막힌다.** 계측은 화면 진입·이탈·클릭마다 발생해 한 세션에 수십 건이 나간다. 막아야 할 것과 정상 트래픽을 갈라 놓았다.
- `limit_conn 100` + `client_body_timeout`/`client_header_timeout`/`send_timeout` 15s → Slowloris·연결 고갈 방어.
- **값 선정 근거**: 제한 기준이 IP 단위라, 경로당·복지관·발표장처럼 여러 어르신이 같은 와이파이(하나의 공인 IP)를 쓰는 상황을 고려했다. 확인 1건이 약 5회 호출이므로 `60r/m + burst 30`은 한 IP 뒤 12명이 동시에 확인해도 걸리지 않는다. 이 설정의 목적은 단일 IP 폭주와 느린 연결 고갈의 제거다.

**검증 결과 (프로덕션 실측, 전부 `?mock=1`이라 API 비용 0원)**

| 항목 | 결과 |
|---|---|
| `nginx -t` 문법 검사 | successful |
| 사이트 정상 동작 | `/` 200, `/health` 200 |
| API 라우팅 | `POST /checks`·`/dialogue`·`/verdict`, `GET /evidence`·`/errors/codes`, `POST /events` 전부 200 |
| 레이트리밋 실동작 | 40건 연속 → **200 33건 / 429 7건**, 차단 발생 확인 |
| 정상 트래픽 분리 | 차단 중에도 `/errors/codes`·`/events` 200 — 계측 안 막힘 |
| 버킷 회복 | 35초 후 정상 200 복구 |

### 1-2. 보안 응답 헤더 — 조치 완료

`X-Frame-Options`/CSP, `X-Content-Type-Options`, `Referrer-Policy`, HSTS가 모두 없었고 `server_tokens`도 켜져 있던 것을 조치했다.

- 적용: `X-Frame-Options: DENY`(클릭재킹 방어) + `X-Content-Type-Options: nosniff` + `Referrer-Policy: same-origin` + `Strict-Transport-Security: max-age=31536000` + `server_tokens off`(버전 은닉).
- `add_header` 상속 규칙 때문에 자체 헤더를 가진 `location = /sw.js`에도 중복 선언.
- 프로덕션 응답에서 헤더 존재와 버전 은닉을 실측 확인했다.
- 클릭재킹은 이 서비스에서 특히 중요하다 — 곁눈을 iframe에 넣고 투명 버튼을 덮으면 판단 버튼(따라한다/안 한다) 클릭을 조작할 수 있고, 이는 잘못된 안내가 나가는 것과 같은 결과다.

### 1-3. 보관 기간(retention) 자동 삭제 — 복구 완료

- 90일 초과 관측 로그(`events`/`error_logs`) 자동 삭제 잡(`api/tools/purge_old_records.py`)이 매일 실행되도록 복구했다. 실행 시각과 삭제 건수를 로그로 남겨(0건도 성공으로 기록) 운영자가 확인할 수 있다.
- **2026-08-16 갱신**: 확인 기록(`checks`)이 프로세스 메모리에서 Postgres 로 옮겨졌다(#33 3단계). 그에 맞춰 삭제 대상에 `checks` · `evidence` · `taggings` 를 추가했다. 자식(evidence/taggings)을 먼저, 부모(checks)를 나중에 지운다(FK 순서). 이로써 **"90일 삭제" 서술이 확인 기록에도 실제로 적용된다.** 그 전까지는 관측 로그 2종에만 참이었고, 확인 기록은 "재시작 시 소멸"에 기대고 있었다 — 그 특성은 이제 없다.
- `device_id`는 SHA-256 해시로만 저장되고 원문·입력 내용은 저장하지 않는다(아래 2-5 참고).

### 1-4. API 문서 노출 — 방어적 차단 (원래도 외부 도달 불가)
- 최초에 "`/docs`가 공개된다"고 의심했으나 **오탐**이었다. nginx는 `/api/`와 `/health`만 프록시하므로 `https://.../docs`는 SPA(`index.html`)로 폴백되고, api 컨테이너는 `127.0.0.1:8000`에만 바인딩돼 외부 직접 접근이 불가능하다.
- 그럼에도 프록시 규칙이 넓어져도 새지 않도록 nginx에서 `/docs`·`/redoc`·`/openapi.json`을 방어적으로 404 처리했다.

## 2. 점검 결과 — 이상 없음 (양호한 영역)

억지로 문제를 만들지 않기 위해, 점검했으나 문제를 찾지 못한 항목을 기록한다. (심사 대응 근거)

- **비밀 유출 없음**: gitleaks가 커밋을 전수 스캔해 올린 후보는 **전부 오탐**(공개 URL의 `uniqueKey=` 파라미터, 코퍼스 문서 식별자)이었다. `.env`가 히스토리에 올라간 이력 없음(`.env.example` 템플릿만 커밋됨). 상세는 [`vulnerability_scan.md`](vulnerability_scan.md) §1.
- **SQL 인젝션 표면 없음**: raw SQL·`text()`·문자열 조립 쿼리가 없고 DB 접근은 SQLAlchemy ORM 파라미터 바인딩만 쓴다. 사용자 입력이 SQL로 들어가는 경로 자체가 없다.
- **XSS 표면 없음**: `dangerouslySetInnerHTML`·`innerHTML`·`eval`·`document.write`·`new Function` 미사용. 입력물이 사기 문자인 이 서비스에서 가장 중요한 방어가 되어 있다.
- **CSRF 해당 없음**: 쿠키·세션·인증이 없고 `allow_credentials=False`라 교차 사이트 요청으로 얻을 권한이 없다.
- **파일 시그니처 검증**: `ocr.py:86-100`이 매직 바이트로 jpeg/png/gif/webp를 판별하고 클라이언트의 `content_type`을 신뢰하지 않는다(확장자 위조 방어).
- **경로 조작·이미지 디스크 기록 없음**: 업로드 이미지를 파일로 저장하는 코드가 없다(메모리에서만 처리). 저장 경로에 사용자 입력이 들어가는 지점이 없다.
- **압축폭탄 없음**: 이미지를 디코딩하지 않고 base64로 API에 전달만 한다. 메모리 내 팽창 경로가 없다.
- **SSRF 경로 없음**: 사용자가 준 링크를 서버가 따라가는 경로(`ocr.extract_from_link`)는 미구현(`NotImplementedError`). (구현 시 내부 IP·메타데이터 차단·타임아웃·리다이렉트 제한을 넣을 것 — 코드 주석에 일부 인지됨)
- **비밀 관리 양호**: `.env`가 git 이력에 없고 `.gitignore`가 `.env`/`.env.*`/`*.key`/`secrets/`를 제외한다. 하드코딩된 API 키를 찾지 못했다(전부 `os.getenv`/`settings` 경유). 프론트 번들에 노출되는 비밀값 없음. `HealthResponse`는 키 존재 여부(boolean)만 노출.
- **DB 개인정보 최소화**: `models/db.py`에 원본 이미지·`raw_text` 컬럼이 없고(주석으로 금지 명시), `device_id`는 SHA-256 해시로만 저장. 마스킹 텍스트만 저장.
- **DB 외부 미노출**: `docker-compose.yml`의 postgres는 호스트 포트를 열지 않고 도커 내부 네트워크에서만 접근된다. `api`는 `127.0.0.1:8000`에만 바인딩.
- **오류 코드 체계(배점 항목)**: 정의된 17종이 전부 실제 발생 지점에서 사용된다(정의만 되고 안 쓰이는 코드 없음). 서버 단일 소스(`error_codes.py`)를 `/errors/codes`로 프론트에 내려 중복 정의를 피한다.
- **조용한 폴백(배점 항목)**: 브리핑이 지적한 "인덱스 메타데이터 불일치로 임베딩이 조용히 거부되고 BM25로 폴백" 문제는 `embeddings.py:238-256`에서 2026-08-05 수정됨(저장/검증이 `_index_metadata()` 한 곳 공유). 그 외 폴백(임베딩→BM25 `EX-003`, 질문 재생성 `GN-001`, 태깅 `GN-002`, 이벤트 저장 실패 `ST-003`)은 모두 `log_incident()`로 서버가 빈도를 인지하도록 연결.
- **판정 억제 원칙**: `verdict_hint`는 `needs_check`/`partially_matched`/`no_source_found`만 반환하고 true/false를 담지 않는다(`schemas.py:27`, 스키마 레벨 강제).
- **프롬프트 인젝션 구조 방어**: 사용자 텍스트가 system이 아닌 user 메시지로 분리 전달되고, 이미지에서 뽑은 텍스트도 동일 방어를 받는다. 생성 결과의 판정어는 사후 차단·재생성되며, 지어낸 URL은 화이트리스트(`allowed_refs`)로 제거된다. 적대적 테스트(`tests/test_guardrail_adversarial.py`)가 판정어 누출을 검사한다.
