# 박진영 | 곁눈(Gyeotnun) 프로젝트 케이스 스터디

**제8회 K-디지털 트레이닝 해커톤 장려상 · Second Look 6인 팀 · 2026년 7~8월**

> 받은 문자·이미지의 진위를 AI가 대신 판정하는 대신, 위험 신호와 공식 근거를 보여주고 사용자가 스스로 확인하도록 돕는 서비스입니다.

## 내 역할과 문제

팀의 [역할 문서](../CONTRIBUTING.md)에서 제 담당은 **백엔드·배포 / API·DB·배포**로 기록돼 있습니다. 문자·이미지 입력부터 근거 검색, 질문, 판단 기록까지의 서버 흐름과 배포 환경이 담당 범위입니다. 검색·프롬프트·프론트 등은 별도 팀원 담당이며, 아래 성과는 팀 공동 결과입니다.

시니어 대상 서비스에서 가장 위험한 실패는 **근거가 없거나 틀렸는데도 확신하는 화면**입니다. 그래서 단순 정답률보다 근거의 출처, 실패 시의 동작, 재현 가능한 평가를 중요하게 다뤘습니다.

## 구현에서 확인할 수 있는 선택

1. **확정 판정 대신 확인 흐름.** [API 라우터](../../api/routers/)는 입력·대화·판단을 분리합니다. 공식 근거를 찾지 못하면 있는 것처럼 꾸미지 않고, 사용자가 확인할 다음 행동을 안내하도록 설계했습니다. 전체 구조와 실제 한계는 [README 기술 구성](../../README.md#기술-구성) 및 [구현 범위](../../README.md#구현-범위와-검증-경계)에 공개했습니다.
2. **실패를 드러내는 평가.** 초기 소규모 평가의 높은 수치에 머무르지 않고 평가셋을 확대하고 홀드아웃을 분리했습니다. 2026-08-21 기준 확대 112건과 홀드아웃 30건에서 **확신 상태의 오답 근거 0건**이었지만, 이는 해당 평가셋에서의 관측값이지 일반적 안전성 보증은 아닙니다. [측정 결과](../../README.md#측정-결과) · [평가 자료](../evaluation/)
3. **운영 사고를 재발 방지 도구로 환원.** 테스트 데이터 삭제 중 조건 불일치로 운영 기록 262행이 지워진 사건을 [사고 기록](../reports/2026-08-17_사고기록_events_262행_삭제.txt)에 남겼습니다. 이후 [삭제 도구](../../api/tools/delete_rows.py)에 예상 행 수 확인과 복원 리허설을 넣었습니다. 실패를 숨기지 않고 설계 규칙으로 바꾼 사례입니다.

## 결과와 검증 경계

- **수상:** 제8회 K-디지털 트레이닝 해커톤 장려상. 상장 원본은 추후 추가 예정입니다.
- **재현:** 현재 서버 VM은 운영하지 않습니다. [정적 브라우저 데모](https://zln02.github.io/gyeotnun/)는 합성 사례의 고정 응답이며 OCR·검색·LLM을 호출하지 않습니다.
- **화면 증거:** [43초 시연 영상](gyeotnun-screen-walkthrough.mp4)은 저장소의 [과거 앱 화면 캡처](../demo/)를 확대·패닝으로 재구성한 것입니다. UI와 글자는 생성하지 않았고 캡처 픽셀을 그대로 씁니다. 내레이션은 **espeak-ng TTS 합성**이며 사람이 녹음한 음성이 아닙니다. 실시간 조작 녹화나 현재 라이브 서비스의 증거가 아니고, 입력은 합성 사례입니다. 제작 방식과 재생성 절차는 [영상 제작 템플릿](영상제작_템플릿.md)에 있습니다. 실제 조작 녹화 원본은 저장소에서 찾지 못했습니다.
- **남은 검증:** 60대 사용자 대상 대면 효과 테스트를 완료하지 못했습니다. 판단 행동 로그의 핵심 프론트 연동도 미완료여서 **판단력 향상**은 입증하지 않았습니다.

**기여 표기 주의:** 당시 상당수 커밋이 서버 공용 `Ubuntu` 계정으로 남아, Git 이력만으로 개인별 코드 작성량을 증명할 수 없습니다. 이 페이지의 담당 표기는 [팀 역할 문서](../CONTRIBUTING.md)에 근거하며, 특정 파일을 단독 작성했다고 주장하지 않습니다.
