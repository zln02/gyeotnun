# 곁눈 시연 영상 — 원고 · 장면표 · 재제작 템플릿

**대상 산출물:** [`gyeotnun-screen-walkthrough.mp4`](gyeotnun-screen-walkthrough.mp4) · [`gyeotnun-screen-walkthrough.srt`](gyeotnun-screen-walkthrough.srt)
**최종 생성:** 2026-09-30 · 42.89초 · 1920×1080 / 30fps / H.264 · AAC 22.05kHz 모노

이 문서는 세 가지 목적을 가진다.

1. 영상에 쓰인 **내레이션 원고와 타임코드별 장면표**를 남긴다.
2. 같은 영상을 **명령 두 줄로 재생성**할 수 있게 한다.
3. 나중에 **상장 원본·실제 화면 녹화·더 나은 음성**을 받으면 **어디를 바꾸면 되는지** 명시한다.

---

## 0. 표기 규칙 (먼저 읽을 것)

이 영상은 포트폴리오 자료이므로, 사실 경계를 넘는 표현을 쓰지 않는다. 아래는 **바꾸더라도 유지해야 하는 규칙**이다.

| 규칙 | 이유 |
|---|---|
| 화면의 UI·글자를 생성·재작성하지 않는다. `docs/demo/` 의 실제 캡처 픽셀만 쓴다 | 만든 적 없는 화면을 보여주면 작업물 증명이 아니라 허위 표시가 된다 |
| 확대·패닝·전환·자막·강조 테두리까지만 연출로 허용 | 원본 화면을 왜곡하지 않는 범위 |
| 하단 고지 띠를 **모든 프레임**에 유지 | 중간부터 본 사람도 성격을 알 수 있어야 한다 |
| 음성은 TTS 합성임을 명시. 사람이 녹음했다고 하지 않는다 | 현재 espeak-ng 합성 |
| "판단력 향상"·"개인화 루프 완성"을 주장하지 않는다 | 60대 대면 효과 테스트 미실시, 훈련 화면은 고정 예시 |
| 수치는 README [측정 결과](../../README.md#측정-결과)의 평가셋·날짜 범위로만 설명 | 확대 112건 / 홀드아웃 30건 / 2026-08-21 기준 |
| 배경음악은 넣지 않았다 | 저작권이 확실한 음원이 없으면 넣지 않는다 |

**상시 고지 문구(하단 띠, 전 구간 고정):**

```
과거 화면 캡처 기반 재구성 · 합성 입력 · 현재 서버 미운영 · 정적 데모 별도 제공
```

## 2. 내레이션 원고

자막 파일(`.srt`)과 화면 좌측 본문에 같은 문장이 들어간다. 원고를 고치면 **`scripts/tts_ko.py` 의 `NARRATION` 배열만** 고치면 되고, 자막·음성·화면 문구가 함께 갱신된다.

| 장면 | 내레이션 | 화면 제목 |
|---|---|---|
| `s0_title` | 곁눈. 받은 문자와 이미지를 스스로 확인하도록 돕는 시니어 정보판단 코치입니다. | (타이틀) |
| `s1_input` | 받은 사진을 그대로 올립니다. 진위를 대신 정해 드리지 않습니다. | 받은 사진을 그대로 올립니다 |
| `s2_signal` | 확인할 점이 남으면 그 이유를 먼저 보여 주고, 무엇을 확인할지 질문으로 여쭤봅니다. | 판정 대신 확인 질문 |
| `s3_evidence` | 질문 옆에 금융위원회 같은 공식 자료를 붙여, 직접 눌러 확인하게 했습니다. | 눌러서 직접 확인 |
| `s4_decision` | 판단은 사용자가 합니다. 미뤄 두는 선택도 그대로 기록합니다. | 미뤄 두는 것도 선택 |
| `s5_training` | 확인한 내용과 비슷한 유형으로 오분 연습을 제공합니다. 화면 실습은 고정 예시입니다. | 비슷한 유형으로 반복 |
| `s6_end` | 과거 화면 캡처로 재구성한 영상이며, 현재 서버는 운영하지 않습니다. | 이 영상에 대하여 |

> `s5_training` 의 "화면 실습은 고정 예시입니다" 는 **지울 수 없는 문장**이다. 이 문장이 빠지면 개인화 루프가 동작하는 것처럼 읽힌다.

마지막 장면에 표로 노출되는 고지 5종:

| 항목 | 문구 |
|---|---|
| 영상 구성 | 저장소의 과거 앱 화면 캡처(docs/demo/)를 확대·패닝으로 재구성. UI·글자 생성 없음 |
| 입력 사례 | 합성 사례. 실제 이용자의 문자나 개인정보가 아님 |
| 음성 | espeak-ng TTS 합성. 사람이 녹음한 음성이 아님 |
| 서버 상태 | 현재 서버 미운영. 정적 브라우저 데모는 zln02.github.io/gyeotnun 에서 별도 제공 |
| 미검증 | 60대 대면 효과 테스트 미실시. 판단력 향상은 입증하지 않음 |

## 3. 재생성 방법

```bash
pip install espeakng-loader pillow numpy --break-system-packages   # 최초 1회
cd <저장소 루트>

python3 docs/portfolio/scripts/tts_ko.py /tmp/gyeotnun-audio
python3 docs/portfolio/scripts/build_video.py \
    --audio-dir /tmp/gyeotnun-audio \
    --demo-dir  docs/demo \
    --out       docs/portfolio
```

필요한 것: `ffmpeg`/`ffprobe`, Python 3.10+, Noto Sans CJK KR 폰트
(`/usr/share/fonts/opentype/noto/NotoSansCJK-{Regular,Bold}.ttc`, KR 인덱스 1).
폰트 경로가 다르면 `build_video.py` 의 `FONT_B` · `FONT_R` · `KR_INDEX` 를 고친다.

생성 직후 확인:

```bash
ffprobe -v error -show_entries format=duration -show_entries stream=codec_name,width,height \
        -of default=noprint_wrappers=1 docs/portfolio/gyeotnun-screen-walkthrough.mp4
ffmpeg -hide_banner -i docs/portfolio/gyeotnun-screen-walkthrough.mp4 \
       -af volumedetect -f null - 2>&1 | grep -E "mean_volume|max_volume"
```

기대값: 약 42.9초 · h264 1920×1080 · `max_volume` 이 0dB 미만(클리핑 없음).

## 4. 교체 절차 — 아직 없는 자료를 받으면

### 4-1. 상장 원본 (현재 없음)

상장 이미지를 받으면:

1. `docs/portfolio/award/` 에 원본을 둔다 (예: `kdt-hackathon-8th-award.jpg`).
2. 개인정보(주민등록번호·주소·서명 등)가 찍혔는지 먼저 확인하고, 있으면 가린 사본을 쓴다.
3. `build_video.py` 의 `SCENES` 에 장면을 추가한다.

```python
"s0b_award": {
    "kind": "screen",
    "shot": "../portfolio/award/kdt-hackathon-8th-award.jpg",
    "pan": (0.0, 0.0),
    "step": "수상",
    "title": "제8회 K-디지털 트레이닝 해커톤 장려상",
    "note": "상장 원본",
},
```

4. `tts_ko.py` 의 `NARRATION` 에 같은 `id` 로 문장을 추가한다(배열 순서 = 영상 순서).
5. README 의 "아직 없는 자료" 목록에서 상장 항목을 지운다.

> 상장을 넣기 전까지 **상장 이미지·링크를 만들어 두지 않는다.** 없는 파일을 가리키는 링크는 만들지 않는다.

### 4-2. 실제 화면 녹화 (현재 없음)

라이브 조작 녹화본이 생기면, 지금의 "캡처 재구성"과 **성격이 다르므로 파일을 분리**한다.

1. 녹화본은 `docs/portfolio/gyeotnun-live-recording.mp4` 로 **별도 저장**한다. 이 재구성본을 덮어쓰지 않는다.
2. 상시 고지 띠 문구를 실제에 맞게 바꾼다. 예: `실제 조작 녹화 · 합성 입력 사례 · 촬영 <날짜>`.
3. 마지막 장면 고지 표의 "영상 구성" 행과 "서버 상태" 행을 실제 상태로 고친다.
4. README 의 영상 항목을 두 개로 나눠, 무엇이 재구성이고 무엇이 실제 녹화인지 구분해 적는다.

### 4-3. 더 자연스러운 음성 트랙

현재 음성은 espeak-ng 포먼트 합성이라 기계음에 가깝다. 상용 TTS나 직접 녹음으로 바꾸려면:

1. 장면별 WAV 를 `s0_title.wav` … `s6_end.wav` 와 **같은 파일명**으로 준비한다.
2. `narration.json` 의 `tts_duration` 을 실제 길이로 맞춘다. 아래로 일괄 갱신할 수 있다.

```bash
python3 - <<'PY'
import json, subprocess, pathlib
d = pathlib.Path("/tmp/gyeotnun-audio")
m = json.loads((d / "narration.json").read_text(encoding="utf-8"))
for sc in m["scenes"]:
    out = subprocess.run(["ffprobe","-v","error","-show_entries","format=duration",
                          "-of","default=nw=1:nk=1", str(d / sc["wav"])],
                         capture_output=True, text=True).stdout.strip()
    sc["tts_duration"] = round(float(out), 3)
m["engine"] = "<사용한 엔진 이름>"
(d / "narration.json").write_text(json.dumps(m, ensure_ascii=False, indent=2), encoding="utf-8")
PY
```

3. `build_video.py` 를 다시 돌린다. 장면 길이·자막 타임코드가 새 음성에 맞춰 자동으로 다시 계산된다.
4. **마지막 장면 고지 표의 "음성" 행과 README 의 제작 방식 설명을 함께 고친다.** 사람이 녹음한 경우에만 "직접 녹음"이라고 적는다.

## 5. 파일 구성

```
docs/portfolio/
├─ gyeotnun-screen-walkthrough.mp4   결과 영상 (자막 번인 + 내레이션)
├─ gyeotnun-screen-walkthrough.srt   별도 자막 파일
├─ 영상제작_템플릿.md                 이 문서
├─ 박진영_케이스스터디.md              개인 케이스 스터디
└─ scripts/
   ├─ tts_ko.py                      내레이션 합성 (원고도 여기 있음)
   └─ build_video.py                 장면 정의 · 렌더 · 자막 생성
```

원본 캡처는 `docs/demo/` 에 있고 이 영상은 그 파일들을 **읽기만** 한다.
캡처를 다시 찍으려면 `tests/demo_screenshots.mjs` 를 쓰되, 그 스크립트는 **배포된 앱**을 대상으로 작성돼 있어 서버가 없는 현재 상태에서는 그대로 동작하지 않는다.
