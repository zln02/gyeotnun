## 1. 순서를 지켰다

1단계 **공개 자료에서만** 후보를 뽑고, 2단계에서 평가셋을 셌다.
평가셋 문구를 먼저 보고 어휘를 만들면 그건 평가셋 맞춤이고, 그렇게 만든 수치는
아무것도 말해 주지 않는다.

훑은 공개 문서 **275건**(사기 경보문 + 2026-08-13 수집한 금융위 보도자료).
그중 **53건**에 '전화로 걸게 만드는' 서술이 있었다.

| 표현 | 공개 문서 등장 |
|---|---:|
| 콜센터 | 23 |
| 대표번호 | 10 |
| 고객센터 | 9 |
| 상담원 | 8 |
| 회신 | 7 |
| 상담사 | 6 |
| 해당 번호 · 통화를 유도 | 각 3 |

원문 예시:
> "가짜 고객센터로 연락 유도 → ②범죄에 연루된 것처럼 기망 → ③자금을 이전할 것을…"
> "'라며 가짜 카드회사 고객센터 번호를 알려주고 전화를 하도록 권유한다"

## 2. 세어 보니 — 넓은 그물 12건, 진짜는 2건

확대 112건에서 12건이 걸렸다. **그런데 문장을 하나씩 읽으니 대부분 다른 것이었다.**

| case | 문구 | 판정 |
|---|---|---|
| **S11** | "아래 번호로 즉시 **회신 바랍니다**" | ✅ 진짜 |
| **S36** | "본인이 아니면 **아래 번호로** 즉시 신고하세요" | ✅ 진짜 |
| B05 | "링크 없이 공식 **대표번호**로 문의하라고 적혀 있음" | ❌ **안전한 행동이다** |
| B26 | "**상담원**이 전화로 안내드립니다" | ❌ 기관이 건다(inbound) |
| S33 | "퇴직연금 전문 **상담사**입니다" | ❌ 발신자 신분 사칭 |
| B09 | "이름과 전화번호를 문자로 **회신**하라고 함" | ❌ 문자 회신 · 본질은 개인정보요구 |
| 나머지 5 | S09·S19·S31·S34·B21·B27 | 이미 다른 유형으로 검출 중 |

### ★ B05 는 반드시 짚어야 한다

> "링크 없이 **공식 대표번호로 문의**하라"

이건 **곁눈이 자기 화면에서 권하는 바로 그 행동**이다 — `verdict.js` 의
`'기관 대표번호로 확인해 보세요'`. **`대표번호`·`고객센터`·`콜센터`를 위험 어휘에
넣으면, 안전한 안내를 위험행동으로 뒤집는다.** 공개 자료 등장 빈도가 가장 높은
세 단어가 하필 이것들이라(콜센터 23 · 대표번호 10 · 고객센터 9), 빈도만 보고
고르면 정확히 이 함정에 빠진다.

## 3. ★ 지금 추가해도 tier 는 하나도 안 바뀐다 (실측)

메모리에서만 `RISK_ACTION_KEYWORDS` 에 `전화회신유도` 를 넣고 전수 재측정했다.

```
tier 변경 0건
확대112  정상오판 1/37→1/37 · 사칭경고 18/37→18/37 · 축2있음 19/39→19/39 · 축2없음 2/70→2/70
홀드30   정상오판 1/10→1/10 · 사칭경고  4/10→ 4/10 · 축2있음  4/11→ 4/11 · 축2없음 3/18→3/18
```

**왜 0건인가** — `detect_risk_action` 의 결과는 오직 `urgency_pressure` 를
`attention` 으로 유지할지 `info` 로 내릴지를 가르는 데에만 쓰인다(`search.py` 두 곳).
그런데 S11·S36 은 **`urgency_pressure` 자체가 안 뜬다.**

```
S11  detect_signals → (없음)          signals: [official_source_found(info)]
S36  detect_signals → (없음)          signals: [no_official_source(attention)]
     "오늘 안에" · "즉시" 가 urgency_pressure 어휘에 없다
```

### 그래서 이 항목의 성격이 바뀐다

'전화 회신 유도'는 **위험행동 유형을 하나 더 추가하는 문제가 아니다.**
위험행동을 **독립된 화면 신호로 내보내기로 결정한 뒤에야** 의미가 생긴다 —
그게 `본선과제_경고이유_화면표시.md` 의 1번 항목이다. **순서가 거꾸로다.**

지금 유형만 늘리면 코드는 늘고 동작은 그대로다.

## 4. #43 어휘 보강 후보 — 계열을 나눠 올린다

| 계열 | 후보 어휘 | 판단 |
|---|---|---|
| **A. 회신 요구** | 회신 바 · 회신하세요 · 회신 주 · 다시 전화 · 전화 주 · 연락 주 | **올린다.** 사용자가 거는 행동을 직접 지시한다 |
| **B. 번호 지정** | 아래 번호로 · 이 번호로 · 해당 번호로 · 하단 번호 | **올린다.** 단 "공식/대표" 가 함께 오면 제외하는 예외가 필요하다 |
| **C. 창구 사칭** | 대표번호 · 고객센터 · 콜센터 · 상담원 · 상담사 · 안내센터 | **올리지 않는다.** §2 의 B05·B26·S33 이 전부 오검출이다 |

### ★ 어휘 출처 문제 — #43 전체에 걸린다

**경보문은 수법을 3인칭으로 서술하고, 사기 문자는 1인칭 명령형이다.**

| | 문장 |
|---|---|
| 공개 경보문 | "가짜 고객센터 번호를 **알려주고 전화를 하도록 권유한다**" |
| 실제 사기 문자 | "**아래 번호로 즉시 회신 바랍니다**" |

**겹치는 단어가 거의 없다.** 그래서 공개 경보문에서 뽑은 어휘를 그대로 탐지
어휘로 쓸 수 없다. 위 A·B 계열도 §2 에서 실제 문자를 읽고 정리한 것이라,
**그대로 채택하면 평가셋 맞춤이다** — 채택하려면 사기 문자 원문 코퍼스가
따로 있어야 한다. `real_sms_normal_11.csv` 같은 실사용 원문이 그 후보인데
지금은 11건뿐이고 전부 정상 문자다.

이건 '전화 회신 유도' 하나의 문제가 아니라 **#43 어휘 보강 전체의 전제**다.
