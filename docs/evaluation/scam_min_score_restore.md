# 사기사례 매칭 하한선(min_score) 복구 — 사전 진단·적용·검증 (2026-08-08)

> 지시: "match_scam_cases 의 min_score 를 실제로 적용하라. 하한선만 살린다."
> 범위 제한: `has_confident_source` 의 `or bool(matched_scam)` 미변경 / 임계값 0.679 미변경 /
> `prompt_chain.py` 미변경. 값도 기존 기본값 **5.0 을 그대로** 썼다(새로 튜닝하지 않음).

## 1. 무엇이 빠져 있었나

2026-08-05 판정축 변경(어휘 합산 → 수법 카테고리 일치) 때 `min_score` 인자가
**코드에서 빠졌다**. 함수 시그니처에는 `min_score: float = 5.0` 이 남아 있었지만
본문 어디에서도 참조하지 않았다.

결과: **하한선 없음.** 수법 카테고리 1개 + 키워드 1개만 겹치면 근거로 승격됐다.

```
B07(대출 이미지)  단어 '은행' 1개  → C09 금융위원회 카드뉴스가 근거로 붙음
                  단어 '직원' 1개  → C12 경찰청 투자리딩방 사기유형이 근거로 붙음
```

이 근거가 `signals` 에 "이전에 확인된 사기 수법과 비슷합니다(권위자사칭)" 로 실려
프롬프트에 들어갔고, 질문 생성까지 오염시켰다.
→ `docs/reports/2026-08-08_은행명질문_금융위근거_원인조사.txt`

### 2-2. ★ S02 와 B07 을 가르는 임계값은 존재하지 않는다

> **S02(사칭) 3.34 < B07(경계 오매칭) 3.85**

B07 을 떨어뜨리려면 3.85 초과가 필요하고, 그러면 S02(3.34)는 반드시 함께 떨어진다.
숫자를 사이에 끼워 넣을 공간이 없다. **하한선을 살리는 한 감수해야 하는 비용이다.**
S02 를 살리려고 임계값을 3.5 쯤으로 낮추면 B07 오매칭이 그대로 남는다 —
그건 이번 수정의 목적 자체를 없앤다. 숫자를 사례에 맞춰 조정하지 않았다.

## 3. 적용한 변경 — 5줄

`services/corpus_index.py` `match_scam_cases()`

```python
lexical = sum(_keyword_weight(k) for k in matched)
# ---- (4) 어휘 하한선. 수법이 같은 범주라도 겹치는 어휘가 이 정도는
#      돼야 '같은 수법'이라 부를 수 있다. 단어 하나짜리 우연한 겹침을
#      근거로 승격시키지 않기 위한 관문이다.
if lexical < min_score:
    log.debug(...)
    continue
scored.append(((len(shared), lexical), matched, case))
```

카테고리 게이트는 '무엇을 요구하는가'만 본다. 정상 서술문도 통과할 수 있다
(B07 "대출상품을 설명하고 상담을 권함" → `loan_bait` 게이트 통과).
하한선은 그 뒤에서 '얼마나 겹치는가'를 보는 **두 번째 관문**이다.

건드리지 않은 것: `has_confident_source` 의 `or bool(matched_scam)`,
임계값 0.679, `match_evidence` 의 `min_score`, `prompt_chain.py`.

## 5. ① 은행명 환각 재확인 — 같은 입력 3회 재생성

프롬프트 입력이 이렇게 줄었다(사기사례 신호 2건·근거 2건 제거):

```
[확인이 필요한 지점]
- 공식 자료와 대조했습니다: 보건복지부·한국사회보장정보원 - 소상공인지원(융자)

[사용할 수 있는 실제 출처]
- 소상공인지원(융자) | bokjiro.go.kr
```

| # | 수정 전 (환각) | 수정 후 |
|---|---|---|
| 1 | 소속 은행 이름·직원 이름·**직통 전화번호**·**대표번호** | "대출상품 **이름**을 정확히 알고 계신가요?" — 환각 없음 |
| 2 | 은행 **대표번호**로 전화 | "**은행 이름 말고 상품 이름**을 확인" — 환각 없음 |
| 3 | **명함이나 문자에 적힌 번호** 말고 대표번호로 | "은행 직원이 어느 **기관 이름**을 말했는지" — 환각 없음 |

- **입력에 없는 물건(명함·문자·직통번호·대표번호)을 지어낸 사례: 3/3 → 0/3**
- 3회 모두 근거 URL 이 fsc.go.kr(무관한 금융위) → **bokjiro.go.kr(실제 관련 문서)** 로 바뀌었다.
- #2 의 "은행 이름"은 *"은행 이름 말고 상품 이름을 확인하라"* 는 **부정문**이라
  없는 사실을 전제하지 않는다. 환각으로 세지 않았다.

→ **근거 품질을 고치니 질문 품질이 따라 올라갔다.** 프롬프트 문제로 보이는 잔여
  증상은 이번 3회에서 나오지 않았다. `prompt_chain.py` 는 손대지 않았다.

★ 3회 표본이다. 사라졌다고 단정할 수 없고 **재현되지 않았다**까지만 말한다.

## 6. C12 오분류 — 데이터 라벨 문제 (코드 수정 없음, 기록만)

`corpus/사례_20-46건_재라벨링표.csv:13` C12

| 필드 | 값 |
|---|---|
| 분류 | 유명인·기관 사칭 / 리딩방 / 가상자산 투자 |
| 수법 | "유명 유튜버·경제인·**투자회사 직원**을 사칭하고 … 가상자산 투자를 **권유**한 사례" |
| **피해결과** | "투자금 손실 \| 명의도용 **인터넷대출** 위험" |

**대출과 무관한 투자리딩방 사례인데 `loan_bait` 로 분류된다.**
`loan_bait` = (대출·대환·저금리…) AND (가능·승인·권유·안내·신청·상담).
- '대출' → **피해결과** 필드의 "인터넷대출"
- '권유' → 수법 설명의 "권유한 사례"

원인: `_blob` 이 레코드의 **모든 필드를 이어 붙인다.** 그래서
**'피해 결과'로 적힌 단어가 '수법'으로 읽힌다.** 카테고리 판정에 쓸 필드를 고르지
않은 것이 구조적 원인이다(C12 만의 문제가 아니다).

이번 하한선 복구로 C12 의 실질 피해는 사라졌다(B07 3.85·S04 4.26 모두 탈락).
그러나 **분류 자체는 여전히 틀려 있다.** 어휘가 충분히 겹치는 입력이 오면 다시
붙을 수 있다. 제출 후 처리 후보:
1. 카테고리 판정 대상을 '수법' 필드로 한정(코드) — 다른 사례 재검증 필요
2. C12 라벨에서 피해결과를 카테고리 근거에서 제외(데이터)

## 7. 남은 한계

- **하한선 5.0 은 재측정한 값이 아니다.** 기존 기본값을 되살린 것이다.
  분리 근거(사칭 최저 vs 오매칭 최고)가 겹쳐 있어 **깨끗한 경계가 없다**(§2-2).
- 실사용 SMS 11건은 원본이 리포에 없어 **재구성본**이다. 전/후 같은 문장으로
  비교했으므로 델타 비교는 유효하지만, 절대 수치로 인용하면 안 된다.
- 질문 환각 재검증은 **3회 표본**이다.
- `has_confident_source` 의 `or bool(matched_scam)` 는 지시대로 그대로 뒀다 —
  하한선을 넘은 사기사례 매칭 1건은 여전히 '확신 있는 근거'로 승격된다.
