## 5. ★ S22 는 고쳐지는가 — 절반만이다

```
S22: ok(needs_check) → hold(no_source_found)     사기사례 매칭 0 → 0
```

**초록은 없어진다. 그러나 경고가 되지는 않는다.**

지시문의 전제 — *"matched_scam 경로가 이미 경고로 처리하므로 화면 로직을 고칠 필요가 없다"* —
는 **성립하지 않았다.** 옮긴 KISA 경보문(1,731자)이 `match_scam_cases` 의
하한선(min_score 5.0)을 **통과하지 못했기** 때문이다. 그래서
`OFFICIAL_DOCS` 에서 빠져 근거가 사라졌을 뿐, 사기사례로 잡히지는 않았다.

같은 이유로 나머지 5건(S12·S18·S28·H23·H27)도 전부 `hold → hold` 로 **변화가 없다**
(사기 매칭 0→0). 화면상 개선은 **S22 한 건의 초록 제거**가 전부다.

→ 즉 **화면 로직을 안 고쳐도 되는 게 아니라, 이설만으로는 목적을 다 못 이룬다.**
경고까지 띄우려면 §2 의 A(경보문 매칭 시 attention 신호) 같은 조치가 여전히 필요하다.

## 6. ★ 비용의 정체 — 새 문서가 아니라 기존 사례가 쉬워진다

정상 오판 1→2 를 만든 **N22**(암환자 의료비 지원 안내, 정상)를 열어 봤다.

```
현재  : hint=needs_check       refs=2  attention=[]
이설후: hint=partially_matched refs=3  attention=['similar_scam_case']
        매칭된 사례 → (재라벨링표)     ← 새로 옮긴 134건이 아니다
```

**매칭된 것은 원래부터 있던 재라벨링표 30건 중 하나다.** 새 문서가 붙은 게 아니다.

### 원인: 사례 수가 늘면 IDF 가중치가 통째로 올라간다

`_keyword_weight()` = `log((N_DOCS + 1) / (df + 1)) + 1.0`

| df | N=51 (현재) | N=185 (이설 후) | 증가 |
|---:|---:|---:|---:|
| 1 | 4.258 | **5.533** | +30% |
| 3 | 3.565 | **4.839** | +36% |

**하한선 5.0 은 그대로인데 모든 단어의 가중치가 30% 안팎 올라간다.**
전에 4.0 점이던 경계 케이스가 5.2 점이 되어 하한선을 넘는다.
N22 가 정확히 그 경우다.

### 그래서 물으신 질문의 답

> **"8/8 에 복구한 min_score 하한선이 그 규모를 감당하는가"**
> → **감당하지 못한다.** 하한선은 절대값(5.0)인데 점수 척도가 사례 수에 따라
> 움직이기 때문이다. 3.6배로 늘리면 하한선이 실질적으로 **약 30% 낮아진 것과 같다.**
> 8/8 에 복구한 방어가 규모 변경만으로 다시 무력해진다.

이건 이설을 하든 안 하든 **구조적 취약점**이다. `SCAM_CASES` 를 늘리는 어떤
작업이든(수집 포함) 같은 문제를 일으킨다. 기록해 둔다.

## 7. 정리

| | 결과 |
|---|---|
| **목적 달성** | 절반. S22 초록은 제거되지만 경고가 되지는 않는다 |
| **다른 5건** | 변화 없음 (hold→hold) |
| **비용 1** | 정상 오판 1 → 2 (확대셋). 홀드아웃은 불변 |
| **비용 2** | 축2 헛경고 2 → 4 (2배) |
| **이득** | 사칭 경고 14→16, 축2 있음 38.5%→46.2% (양쪽 세트 모두 상승) |
| **무영향** | 근거 검색 성공률·Top-5 는 양쪽 세트 전부 불변 |
| `OFFICIAL_DOCS` | 1,052 → **918** (기획서 2.3 수치, 정정 이력 필요) |

**채택을 권하지 않는다.** 목적(S22 경고 전환)은 절반만 이뤄지는데,
8/5 에 실측으로 기각했던 오판 문제가 다시 나타나고, 그 원인이 새 문서가 아니라
**IDF 척도 이동**이라 134건보다 적게 옮겨도 정도만 다를 뿐 같은 방향이다.

대안으로는 §2 의 **A안**(경보문이 근거로 매칭되면 attention 신호를 붙인다)이
이설 없이 목적을 달성하고 `OFFICIAL_DOCS` 수치도 건드리지 않는다.
다만 이것도 아직 측정하지 않았다.

**판단은 사람이 한다. 아무것도 옮기지 않았다.**

## 부록 — 이 실험에서 내가 낸 오류 (정정)

1차 시뮬레이션은 **무효였다.** `ci.OFFICIAL_DOCS` 리스트만 바꾸고
임베딩 경로가 실제로 참조하는 `corpus_index._OFFICIAL_DOCS_BY_ID` 딕셔너리를
그대로 뒀다. 그래서 옮긴 문서가 `match_embedding_docs` 에 계속 잡혔고,
S22 가 변하지 않는 결과가 나왔다. 그대로 보고했다면
**"이설해도 S22 는 안 고쳐진다"** 는 반대 결론이 될 뻔했다.
딕셔너리까지 반영하도록 고쳐 재실행한 값이 위 표다.
