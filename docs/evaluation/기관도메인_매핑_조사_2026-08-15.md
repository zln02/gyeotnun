## 2. 표 만드는 법 — 무엇을 어떻게 확인했나

각 기관 공식 사이트에 직접 접속해 **HTML `<title>` 을 읽어 기관명이 나오는지**
확인했다. 통설이나 기억이 아니라 그 도메인이 실제로 그 기관 사이트인지를 본 것이다.

| 확인 결과 | 건수 |
|---|---|
| **제목으로 확인됨** | 28 |
| HTTP 200 이지만 제목 없음(확인 약함) | 4 |
| **★ 확인 못 함** | 3 |

### ★ 확인 못 한 3건 — 표에 그대로 적어 뒀다

| 기관 | 후보 도메인 | 왜 |
|---|---|---|
| 경찰청 | `police.go.kr` | 리다이렉트 루프(상한 초과) |

**통설로는 맞지만 이번 조사로 확인하지 못했다.** 확인한 것처럼 적지 않는다.
사람 검수 때 이 3건부터 볼 것.

### ★ 조사에서 나온 세 가지 함정

**(가) 공공기관인데 `.go.kr`/`.or.kr` 이 아닌 곳이 있다**

```
정부24          gov.kr      ← .go.kr 이 아니다
한국도로공사      ex.co.kr    ← .co.kr
한국전력공사      kepco.co.kr ← .co.kr
```

URL 펼치기의 `.go.kr` 규칙과 **다른 이야기**다. 펼치기는 "도착지가 `.go.kr` 이면
공공기관이다"(참)를 쓰는데, 그 역인 "공공기관이면 `.go.kr` 이다"는 **거짓**이다.
매핑표는 도메인을 개별로 적으므로 문제없지만, **접미사로 기관 여부를 판정하려는
유혹을 여기서 끊어 둔다.**

**(나) apex 도메인이 안 되고 `www.` 가 필요한 곳이 있다**

`nhis.or.kr` · `counterscam112.go.kr` 은 apex 가 DNS 해석조차 안 되고,
`comwel.or.kr` · `kosaf.go.kr` 은 403 이다. **비교는 정확한 호스트명이 아니라
등록가능 도메인(마지막 3라벨: `nhis.or.kr`) 단위로 해야 한다.** 그렇게 하지 않으면
`www.nhis.or.kr` 을 불일치로 판정한다.

**(다) 별도 도메인을 쓰는 서비스가 있다**

`국세청 nts.go.kr` 과 `홈택스 hometax.go.kr` 은 다른 도메인이다. 표에 둘 다 넣었다.
**한 기관 = 한 도메인이 아니다.** 검수 때 누락된 서비스 도메인을 채워야 한다.

## 6. 구현 기록 (2026-08-16)

### 6-1. ★ 조사 §3 의 발동 조건이 그대로였으면 기능이 죽었다

초안 ②는 "본문에 URL 이 있다" 였고, 나는 `url_expand.extract_urls` 를 재사용할
생각이었다. 그건 `http(s)://` 로 시작하는 것만 뽑는다(마스킹된 계좌·전화번호를
주소로 오인하지 않기 위해 일부러 그렇게 만들었다). 그런데 **노린 두 건의 실제
원문에는 스킴이 없다.**

```
S03  정부24 미수령 환급금 확인 gov24-refund-event.com
S08  건강보험료 환급 신청 nhis-refund24.com
```

재사용했으면 **목표 2건이 전부 조용히 침묵했을 것이다.** 테스트도 통과했을 것이다 —
내가 스킴 붙은 예문으로 테스트를 짰을 것이기 때문이다. 원문을 직접 열어 보고서야
알았다. 그래서 `org_domain.extract_domains()` 를 따로 뒀다:

- 스킴이 붙어 있으면 TLD 를 따지지 않는다(`bit.ly` 처럼 목록에 없는 TLD 도 통과)
- 스킴이 없으면 **마지막 라벨이 아는 TLD 일 때만** 주소로 본다
  (그래야 `3.5%` · `오전 9.30` · 마스킹된 `***-***-******` 가 주소로 안 잡힌다)
- 모르는 TLD 는 버린다 = **침묵**한다. 빠뜨렸을 때 사칭을 놓치는 쪽으로 틀리지,
  정상 문자를 의심하는 쪽으로 틀리지 않는다.

### 6-2. 침묵 규칙 두 개를 더 넣었다 (초안에 없던 것)

초안의 침묵은 "일치하면" · "표에 없으면" 둘뿐이었다. 구현하며 오탐 경로 두 개가
더 보였다.

**(b) 받은 주소가 표 안의 *다른* 기관 공식 도메인일 때도 침묵한다.**
조사 §2 "(다) 별도 도메인을 쓰는 서비스가 있다" 를 그대로 규칙으로 옮긴 것이다.
`국세청(nts.go.kr)` 문자에 `hometax.go.kr` 링크가 붙는 것은 정상인데, 초안 규칙만으로는
**불일치로 잡힌다.** 한 기관 = 한 도메인이 아니다.
★ 이 판정에는 `브라우저검수대기` 4행도 센다 — **침묵 쪽은 넓게, 발동 쪽은 좁게.**

**(c) 받은 주소가 `.go.kr` / `.or.kr` 이면 침묵한다.**
표에 없는 공공기관 주소(`129.go.kr` 등)를 오탐하지 않기 위해서다. 근거는
`url_expand.PUBLIC_SUFFIXES` 와 같다(등록 자격 제한).
★ 대가: `.or.kr` 유사 도메인을 쓰는 사칭은 이 규칙으로 못 잡는다. 알고 고른 쪽이다.

### 6-3. 펼친 주소와 원래 주소를 **둘 다** 본다

하나라도 침묵 규칙에 걸리면 침묵한다. 한쪽만 보면 각각 다른 사고가 난다.

| 무엇만 보면 | 무슨 사고 |
|---|---|
| 펼친 주소만 | 죽은 사칭 도메인은 펼치기가 실패한다 → S03·S08 이 빠진다 |
| 원래 주소만 | 진짜 기관이 단축주소를 쓰면 오탐이 난다 (R01 이 그런 문자다) |

외부 접속은 늘지 않는다 — `search.py` 가 `url_expand` 결과를 그대로 넘긴다.

### 6-4. 검수 상태 갱신

| 상태 | 행 | 발동 |
|---|---|---|
| `1차검수` | 28 | ○ |
| `1차검수(외부교차)` | 3 (경찰청·국토교통부·한국소비자원) | ○ |
| `브라우저검수대기` | 4 (복지로·과기정통부·방통위·대법원) | **×** |

확인 못 했던 3건을 외부 검색 + 하위 도메인 실재로 교차 확인했다(2026-08-15).

```
경찰청      minwon.police.go.kr(경찰민원포털) · minwon24.police.go.kr(경찰민원24) ·
            cyberbureau.police.go.kr — 전부 DNS 해석, apex 와 같은 116.67.x 정부 대역
국토교통부   rt.molit.go.kr(실거래가 공개시스템) · stat.molit.go.kr — apex(116.67.32.40)와 같은 대역
한국소비자원 www.kca.go.kr 가 apex 와 같은 210.90.35.216 · 외부 검색에서 공식 사이트로 다수 확인
```

★ 조사에서 덤으로 나온 것: `kco.kca.go.kr` · `crm.kca.go.kr` 은 **`127.0.0.1` 을
반환한다.** 실제로 존재하는 공공기관 하위 도메인이 루프백을 준다 — `url_expand` 의
사설 IP 차단이 이론이 아니라 **실물로 걸리는 사례**다.

★ 발동 자격은 코드 상수가 아니라 표의 `검수상태` 칸이 정한다(`_ACTIVE_PREFIX = "1차검수"`).
검수가 끝난 행의 칸을 `1차검수` 로 바꾸면 **코드를 고치지 않아도 켜진다.**

★ 남은 것: `예금보험공사(kdic.or.kr)` 는 제목이 "제도·정책" 이라 기관명 확인이 약한데
