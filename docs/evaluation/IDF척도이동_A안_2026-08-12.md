## 1. 영향 범위

### (a) BM25 폴백도 N 의존이다 — 같은 문제 있음

`rank_bm25.BM25Okapi._calc_idf`:
```
idf = log(N - df + 0.5) - log(df + 0.5)
```
`_OFFICIAL_MIN_SCORE = 12.0` 은 **절대값**이다.

같은 질의("기초연금 신청 대상과 조건을 알려주세요")로 청크 수만 바꿔 실측했다.

| 청크 수 | 상위 3 점수 |
|---:|---|
| 500 | 7.94 / 5.13 / 4.74 |
| 1,000 | 7.88 / 7.56 / 5.55 |
| **2,012** (현재) | **10.70** / 7.81 / 7.45 |

**`OFFICIAL_DOCS` 를 수집으로 늘리면 BM25 점수도 함께 올라간다.**
다만 BM25 는 **임베딩 실패 시 폴백 경로**에서만 쓰이므로 상시 노출은 아니다.

### (b) 임베딩(코사인)은 코퍼스 크기와 무관하다 — **안전**

문서 300건을 검색 대상에서 제거한 전후로, 남은 문서의 코사인 점수를 비교했다.

```
남은 문서의 점수 일치: 12/12 (오차 < 1e-9)
```

코사인 유사도는 **질의-문서 쌍마다 독립**이라 다른 문서가 늘고 줄어도 값이 변하지 않는다.
`EMBEDDING_MIN_SCORE=0.6155` 는 절대값이지만 **척도가 움직이지 않으므로 안전하다.**

> **→ 제도 안내문 수집(복지로·정부24·국세청·건보·국민연금)은 병행해도 된다.**
> 주 검색 경로의 점수를 흔들지 않는다.
> 단, 수집 후 **BM25 폴백 경로는 따로 재측정**해야 한다(위 (a)).

## 2. 재교정 곡선 — 로그가 아니라 계단이다

`SCAM_CASES` 를 51 / 80 / 120 / 185 로 바꿔 가며
"정상 오판 0 을 유지하는 최소 `min_score`" 를 0.25 간격으로 탐색했다.

| N | **확대 112건** | **홀드아웃 30건** | 현 5.0 에서의 오판 | `log(N+1)` 비 |
|---:|---:|---:|---:|---:|
| **51** (현재) | **6.75** | **11.00** | 1건 | 1.000 |
| 80 | 13.75 | 12.25 | 1건 | 1.112 |
| 120 | 14.00 | 12.75 | 1건 | 1.214 |
| 185 | 14.75 | 13.50 | 1건 | 1.323 |

### 읽어야 할 것 세 가지

**① 현재 N=51 에서도 5.0 은 이미 부족하다.** 정상 오판 0 을 만들려면
확대셋 6.75 · 홀드아웃 **11.00** 이 필요하다. 지금 5.0 으로 돌면서
정상 오판 1건이 나는 것이 이 수치와 일치한다.

**② 로그를 따르지 않는다.** 51→80 에서 6.75→13.75 로 **2.04배** 뛰는데
`log(N+1)` 비는 1.112 다. 이후 80→185 는 완만하다(13.75→14.75).
최소 임계는 **"가장 높은 점수를 받은 정상 케이스 하나"** 가 결정하는 극단값이라,
새 사례 하나가 특정 정상 문서와 강하게 겹치면 계단식으로 튄다.

**③ 그런데 5.0 에서의 실제 오판은 N 과 무관하게 1건으로 불변이다.**
즉 IDF 이동이 **당장 오판을 늘리지는 않고, 안전 여유를 6.75 → 14.75 로 깎는다.**
경계에 가까워지는 것이지 이미 무너진 것은 아니다. 이 구분이 중요하다.

> **→ (라) 절차적 재교정도 생각만큼 안전하지 않다.** 곡선이 예측 가능하지 않아
> "N 이 이만큼 늘면 하한선을 이만큼" 이라는 공식을 만들 수 없다.
> 수집할 때마다 **전수 재측정**해야 하고, 그건 절차라기보다 매번 재실험이다.

## 3. 구조적 해법 후보 (구현하지 않음. 표만)

| 안 | 방식 | 장점 | 위험 |
|---|---|---|---|
| **(가)** IDF 의 N 을 고정 참조값으로 | `log((N_ref+1)/(df+1))+1`, `N_ref=51` 고정 | 척도가 안 움직여 하한선 5.0 의 의미가 보존된다. 변경 한 줄 | **판정 로직 변경.** df 는 여전히 실제 코퍼스 기준이라 N 이 커지면 df 도 커져 가중치가 **내려간다** → 사칭 검출이 떨어질 수 있다. 8/8 사고와 반대 방향의 위험 |
| **(나)** 최대 가능 점수로 정규화 | `lexical / max_possible` → 0~1 | 척도가 코퍼스와 무관해진다. 하한선 해석이 직관적 | **판정 로직 변경.** `max_possible` 정의가 자의적이다(질의 길이? 사례 길이?). 정의를 바꾸면 모든 기존 실측이 무효가 된다 |
| **(다)** 하한선을 상위 백분위로 | 절대 5.0 대신 "상위 N%" | 코퍼스 크기와 자동으로 무관해진다 | **판정 로직 변경 + 성격 변화.** 백분위는 **항상 무언가를 통과시킨다** — 아무것도 안 맞는 정상 문자에도 상위 N% 는 존재한다. "못 찾았다"를 낼 수 없게 되는데, 그건 곁눈의 정체성(확인불가가 기본값)과 정면 충돌한다 |

## 4. ★ A안 측정 — 이설보다 모든 면에서 낫다

경보문이 근거로 매칭되면 attention 신호(`alert_doc_matched`)를 붙인다.
`OFFICIAL_DOCS` 는 그대로 두고 `data_type` 만 본다.

### (a) `data_type` 접근 지점 — 이미 있다

`OfficialDoc` 데이터클래스에 **`data_type: str` 필드가 이미 있다**(`corpus_index.py:222`).
`search.collect_evidence()` 안에서 `matched_official` 을 순회할 때
`doc.data_type in {"warning_case","press_release"}` 로 바로 판별 가능하다.
**코퍼스 재적재도, 인덱스 재빌드도 필요 없다.**

### (b) `verdict.js` — 키 추가가 **필요하다**

8/12 에 초록을 허용 방식(`needs_check` 일 때만 ok)으로 바꿔 뒀으므로,
새 attention 이 붙으면 `hint` 가 `partially_matched` 가 되어 **초록에서는 자동으로 내려간다.**
그러나 **경고(warn)로 올라가려면 `ATTENTION_KEYS` 에 키를 추가해야 한다** — 실측으로 확인했다.
