### 1-1. 인용 표지별 원시 추출

인용 표지 후보 넷을 다 걸었다 — 낫표 `「」『』` · 겹따옴표 · 홑따옴표 · 각괄호,
그리고 "다음과 같은 / 아래와 같은 / 예시 / 문자 내용" 뒤에 오는 덩어리.

**원시 후보 1,356개 · 인용문이 나온 문서 288/312건.**

### 1-2. ★ 걸러 보니 1,356 → 51 → **12**

두 단계로 걸렀다.

1. **자동**: 문자 표지(`[Web발신]`·URL·`고객님`) 또는 1인칭 명령형이 있고,
   3인칭 서술어(`유도한다`·`권유한다`·`밝혔다`)가 없는 것 → **51개**
2. **사람이 읽음**: 그중 실제로 **사기범의 말/사기 문자 원문**인 것 → **12건**

39개가 왜 떨어졌는가 — **명령형만으로는 갈리지 않는다.**

> "급전이 필요한 경우, 우선 서민금융진흥원(☎1397)의 정책금융상품을 **확인하세요**"
> "혼자서 고민하지 말고 피해발생 시 ☎112 또는 ☎1332로 **신고하세요**"

둘 다 완벽한 1인칭 명령형인데 **기관이 시민에게 하는 안전 권고**다.
사기 문자와 문법이 같다. 이건 '전화 회신 유도' 조사에서 B05(공식 대표번호로
문의하라)가 걸렸던 것과 **정확히 같은 함정**이다.

### 1-4. ★ KISA 133건에서 인용문이 0건인 이유 — 원문이 이미지 안에 있다

KISA 인용문 469개를 열어 보면 전부 **기관 발언과 사업명**이다.

> "앞으로도 민간 기업과 협력을 확대해 스미싱 피해 예방에 힘쓰겠다"
> 「개인정보 보호·활용 기술 연구개발 관리규정」

그런데 **경보문류 179건 전부가 `attachment_urls` 를 갖고 있고, 첨부 664장이
전부 이미지다**(kisa.or.kr 575 · counterscam112 89, 문서당 평균 3.7장).
**문자 예시는 본문이 아니라 그림으로 붙어 있다.**

곁눈은 이미 OCR(PaddleOCR)을 갖고 있으므로 **기술적으로는 664장에서 뽑을 수 있다.**
하지 않은 이유는 셋이다.

1. 지시가 "인용문 추출 조사"였고, 이미지 OCR 은 별개 작업량이다
2. 코퍼스 `license` 필드가 이 133건에 대해
   **"공공누리 유형 및 개별 첨부파일 이용조건 확인 필요"** 라고 이미 적어 두었다.
   본문과 첨부의 이용조건이 다를 수 있다는 뜻이다
3. 664장 중 몇 장이 문자 캡처이고 몇 장이 행사 사진인지 모른다 —
   §1-1 에서 본 것처럼 KISA `warning_case` 에는 협약식 기념촬영이 섞여 있다

**규모 추정도 하지 않았다.** 세지 않은 것을 센 것처럼 쓰지 않는다.

## 2. GitHub `Ez-Sy01/KOR_phishing_Detect-Dataset` 라이선스·출처

### 2-1. 라이선스 — **없다. 그러므로 쓸 수 없다.**

| 확인 | 결과 |
|---|---|
| GitHub API `license` | **`None`** |
| `LICENSE` / `LICENSE.md` / `LICENSE.txt` / `COPYING` | **전부 404** |
| README 안 라이선스 문구 | **없음** |

**라이선스가 없는 저장소는 "자유 이용"이 아니라 "저작권자가 전부 보유"다.**
GitHub 이용약관상 포크·열람은 되지만 **복제·재배포·2차 이용은 허락이 없으면 안 된다.**
연구용이라도 마찬가지다. **저자에게 직접 허락을 받기 전에는 쓸 수 없다.**

> 논문은 MDPI *Information* 15(5):265 (2024) 이고 MDPI 논문은 통상 CC BY 지만,
> **논문의 라이선스가 별도 GitHub 저장소를 덮지 않는다.** 조사에서도 논문 본문에
> 데이터 라이선스 문구는 찾지 못했다.

### 2-2. 출처 — 논문 Data Availability 로 확인

> "We collected a total of **615 images directly uploaded by messenger phishing
> victims from 2013 to 2021**, converted them into text, and used them as a
> phishing dataset."

| | |
|---|---|
| 규모 | **피싱 615건** / 정상 42,594건 |
| 원천 | **피해자가 직접 올린 캡처 이미지** 를 텍스트로 변환 |
| 어느 플랫폼에 올렸는지 | **명시 없음** |
| 정상 메시지 | 트위터 대화·원샷 대화·챗봇 대화 데이터셋 (2021) |

**두 번째 위험**: 피해자가 올린 캡처를 텍스트로 변환한 것이라 **개인정보(이름·계좌·
전화번호)가 남아 있을 수 있다.** 곁눈은 실제 개인정보를 쓰지 않는다는 원칙이 있고
(평가셋 전부 합성), 이 데이터는 그 원칙과 정면으로 부딪힌다. 쓰려면 마스킹 검수가
선행돼야 한다.

### 2-3. ★ "2년 전 자료" — 저장소는 2년, **데이터는 5~13년 전이다**

| | 날짜 |
|---|---|
| 저장소 생성 | 2024-04-29 |
| 마지막 push | **2024-08-20** (약 2년 전) |
| **데이터 수집 기간** | **2013 – 2021** |

지시서에 적힌 "2년 전 자료"는 **저장소 기준**이고, 실제 **문자 원문은 2013~2021년**
것이다. 2026년 기준 **5년에서 13년 전**이다.

어휘 노후가 우려 수준이 아니라 확정적이다 — 이 기간에는 다음이 아예 없다.

- 민생회복 소비쿠폰 (2025) · 2차 소비쿠폰 (2025)
- 국가정보자원관리원 화재 악용 (2025)
- 쿠팡 개인정보 유출 피해보상 사칭 (2025)
- 노쇼/대리구매 사기 (2024–)
- 딥페이크 자녀납치 (2024–)

우리 평가셋의 사칭 유형과 겹치는 부분이 **대출·수사기관 사칭 정도**로 좁다.
그건 §1-3 에서 이미 12건 확보한 바로 그 영역이다 — **615건을 어렵게 확보해도
새로 얻는 어휘 영역이 크지 않을 수 있다.**

## 3. 조사 중 확인한 것 두 가지 (기록만 한다)

### (1) ★ `warning_case` 라벨 안에도 C 성격이 최소 23건 있다

`ALERT_DOC_DATA_TYPES = {"warning_case"}` 는 134건 **전부**를 사기 경보문으로 믿는다.
그런데 제목에 협약·시상·출범·공모전·채용·세미나가 든 것이 **23건**이다.

> "한국인터넷진흥원, 카카오뱅크와 스미싱 피해 예방을 위한 기술 협약 체결"
> "'2024 전국 한글도메인 자랑' 공모전에서 공공분야 최우수상 수상"
> "KISA, 개인정보 영향평가기관의 전문인력 채용소식을 한자리에!"

**어제 `press_release` 24건에서 고친 문제의 거울상이다.** 그때는 24건을 사람이
분류해 8건만 허용목록에 넣었는데, `warning_case` 쪽은 라벨을 통째로 믿고 있다.

**단, 지금 실측상 해는 나지 않았다** — 정상 오판 1/37·1/10, 축2 헛경고 2/70·3/18 로
어제 반영 전후 불변이다. 이 문서들이 근거로 매칭되는 일이 드물어서다.
**고치지 않았고, 고치자고 제안하지도 않는다.** 사람이 볼 항목으로 적어만 둔다.

### (2) 코퍼스에 `license` 필드가 이미 있다

| 값 | 건수 |
|---|---:|
| 이용허락범위 제한 없음 | 377 |
| 공공누리 및 원문 이용조건 확인 필요 | 297 |
| 국가건강정보포털 건강정보 저작권 확인 필요 | 164 |
| **공공누리 유형 및 개별 첨부파일 이용조건 확인 필요** | **133** ← KISA 경보문 |
| 공공누리 - 각 기관 저작권정책 확인 | 56 |
| 공식 사이트 저작권정책 확인 필요 | 46 |

**"확인 필요" 가 1,073건 중 696건이다.** 어제 금융위에서 확인한
"공공누리 유형 미표시" 는 예외가 아니라 **코퍼스 전반의 상태**다.
