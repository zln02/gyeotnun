# 본선 과제 — BM25 폴백의 척도 이동 취약점 (2026-08-12 기록)

**지금 고치지 않는다. 본선 과제로 기록만 한다.**

---

## 무엇이 문제인가

`match_official_docs()`(BM25 폴백)의 임계값이 **절대값**인데, BM25 점수 척도는
**코퍼스 크기에 따라 움직인다.**

```python
# rank_bm25.BM25Okapi._calc_idf
idf = log(N - df + 0.5) - log(df + 0.5)        # ← N 의존

# corpus_index.py:806
_OFFICIAL_MIN_SCORE = 12.0                      # ← 절대값
```

### 실측 (2026-08-12)

같은 질의("기초연금 신청 대상과 조건을 알려주세요")로 **청크 수만** 바꿔 쟀다.

| 청크 수 | 상위 3 점수 |
|---:|---|
| 500 | 7.94 / 5.13 / 4.74 |
| 1,000 | 7.88 / 7.56 / 5.55 |
| **2,012** (현재) | **10.70** / 7.81 / 7.45 |

**코퍼스를 늘리면 점수가 함께 올라간다.** 임계값 12.0 은 그대로이므로
**실질적으로 느슨해진다.** 이건 `SCAM_CASES` 쪽 IDF 척도 이동
(`_keyword_weight`, `min_score=5.0`)과 **완전히 같은 구조의 문제**다.

---

## ★ 왜 이게 더 나쁠 수 있는가

`SCAM_CASES` 쪽 문제와 성격이 다른 점이 하나 있다.

**BM25 폴백이 발동하는 상황은 이미 장애 상황이다.**
임베딩 인덱스가 없거나, 모델 로드가 실패했거나, 질의 임베딩이 3초 타임아웃을 냈을 때만
이 경로로 온다(`match_official_docs_safe`, `EX-003` 인시던트가 함께 남는다).

즉 **서비스가 이미 정상이 아닌 순간에, 평소보다 느슨해진 임계값으로 근거를 붙이게 된다.**
장애 중에 오판이 나면 평소의 오판보다 나쁘다 —

- 사용자는 장애 중이라는 사실을 모른다. 화면은 평소와 똑같이 보인다.
- 폴백이 도는 동안 `official_source_found` 가 붙으면 그대로 근거로 제시된다.
- 8/9 에 외부 LLM 이 8시간 동안 100% 폴백이었는데 아무도 몰랐던 전례가 있다
  (그 뒤 `GN-003` 폴백률 관측을 붙였다). 같은 일이 검색 쪽에서 일어나면
  **더 조용히 지나간다** — 검색 폴백에는 아직 그런 관측이 없다.

---

## 지금 고치지 않는 이유

1. **폴백 경로다.** 평상시에는 임베딩(코사인)이 돌고, 코사인은 코퍼스 크기와
   무관함을 실측으로 확인했다(문서 300건 제거 전후 점수 12/12 일치).
   상시 노출되는 위험이 아니다.
2. **임계값 변경은 판정 로직 변경이다.** 8/8 사고가 정확히 그 경로였다.
   지금 손대면 예선 제출 수치가 전부 재측정 대상이 된다.
3. **아직 코퍼스를 늘리지 않았다.** 제도 안내문 수집이 시작되면 그때 실측하면 된다.
