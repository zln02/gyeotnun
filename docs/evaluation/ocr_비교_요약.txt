3. 다크모드 전처리 - 가설은 절반만 맞았다
================================================================

받은 지적: "tesseract 경로가 그레이스케일을 쓰는데 다크모드는 명암이 반대라
            역효과일 수 있다"

맞는 부분 : tesseract 는 다크모드에서 실제로 크게 무너진다
            light 0.847 -> dark 0.591 (-0.256)

틀린 부분 : 명암을 반전시켜도 고쳐지지 않는다
            전처리            전체     light    dark
            그레이스케일       0.751    0.847    0.591
            그레이스케일+반전   0.752    0.846    0.597
            차이              +0.001   -0.001   +0.006   <- n=9 에서 사실상 0

원인 : tesseract 가 내부 이진화(Otsu)에서 밝기 극성을 스스로 판별하므로
       수동 반전은 중복 작업이 된다.

결론 : ★ 조건별 전처리 분기는 넣지 않는 것이 맞다. 코드만 복잡해지고 이득이 없다.
       다크모드 열세의 원인은 극성이 아니라 다른 데 있다(다크 테마의 낮은 대비.
       원인 규명은 하지 않았다).

참고 : easyocr 은 다크모드 영향이 미미하다(0.827 -> 0.804, -0.023).
       딥러닝 검출/인식이라 극성에 견고하다.

5. easyocr 오차의 상당 부분은 인식 실패가 아니라 후처리 미비
================================================================

신규 세트에서 0.819 로 떨어진 주된 이유는 글자를 못 읽어서가 아니라
말풍선 밖 UI 텍스트가 결과에 섞여서다.

  실제 추출 예 (01_s01_light.png, acc=0.902)
    DIDD 8306 김영자 김 이거 우리도 받을 수 잇대요 김영자 김 [정부지원] 어르신
    생활안정 지원금 안내 2026년 미신청자 대상 최대 300만원 신청기한 : 오늘까지

  - 본문([정부지원] 어르신 생활안정 지원금 안내...)은 정확히 읽었다
  - DIDD 8306 = 상태바 아이콘/배터리 오인식
  - 김영자 김 = 발신자명 + 아바타 이니셜

현재 후처리는 대화방 제목과 정해진 UI 패턴만 지운다. 발신자명은 케이스마다
달라 목록으로 처리할 수 없어 못 걸러낸다.

-> 로컬 OCR 의 실제 인식력은 이 수치보다 높다. 말풍선 영역만 잘라내는
   레이아웃 처리를 넣으면 상당 부분 회복될 여지가 있다.
   (이번 범위에서는 정량화하지 않았다)

6. 후보별 판정
================================================================

  easyocr    조건부 가능
             깨끗한 입력에서 일치율 Vision 과 동일, 정상 오판 0건,
             메모리 1.2GB(가용 12GB로 충분). 단 열화 입력에서 붕괴.

  tesseract  부적합
             다크모드 0.591, 정상 라벨 0.563, 장당 26~44초.
             가볍다는 것 외에 장점이 없다.

  PaddleOCR  부적합
             정확도 0.568(깨끗), 16s/장, 피크 2.4GB - easyocr 보다 모든 면에서 열세.
             ※ 단서: 1차 시도가 oneDNN 런타임 오류로 죽어 enable_mkldnn=False 로
               껐다. 이것이 16초라는 느린 속도의 주된 원인이다. 검출 모델도
               server_det(무거움)으로 잡혔다. "튜닝하면 나아질 수 있으나 기본
               구성으로는 easyocr 보다 못하다"가 정확한 서술이다.

  RapidOCR   측정 미완
             기본 번들에 한국어 없음(0.046). 한국어 모델은 PP-OCRv1 시절 것만
             공개돼 있어 붙이려다 중단.

  CLOVA OCR  측정 못 함
             API 키 없음. (보고했던 "어댑터 배선 완료 커밋 8900a9e"는 이 저장소에
             존재하지 않는다 - 커밋도 코드도 키도 0건)

7. 판단: 전면 전환은 비권장, 병행은 유효
================================================================

easyocr 은 깨끗한 입력(카톡에서 그대로 전달받은 스크린샷)에서 기대판단 일치율이
Claude Vision 과 동일한 0.667 이고, 절대조건인 정상 10건 오판도 0건을 지켰다.
다크모드/큰글씨/말풍선잘림 어느 조건에서도 0.80 대로 안정적이며(Vision 대비 -0.17),
메모리도 피크 1.2GB 로 가용 12GB 안에서 운영 서비스와 문제없이 공존했다.
게다가 현재 0.819 라는 수치는 인식 실패가 아니라 후처리 미비 때문이 커서,
말풍선 영역 처리를 넣으면 더 오를 여지가 있다.

반대로 전환을 막는 요인은 두 가지다.
  1) 화면을 다른 폰으로 찍은 사진에서 정확도가 0.534 로 무너지고,
     파이프라인 일치율도 0.667 -> 0.433 으로 떨어진다.
     시니어에게 "화면 찍어서 보내달라"는 상황이 드물지 않다.
  2) 깨끗한 입력에서도 근거검색 성공률이 0.867 -> 0.600 으로 떨어져,
     OCR 오탈자가 검색 품질을 직접 깎는다.

제안: 입력 품질로 갈라 쓰는 병행 구조
  - 스크린샷처럼 깨끗한 이미지 -> 로컬(easyocr)로 처리해 외부 전송 자체를 없앤다
  - 로컬 신뢰도가 낮게 나오면 -> 그때만 Claude Vision 을 호출한다
  이러면 대부분의 이미지가 서버 밖으로 나가지 않으면서 정확도 손실도 막을 수 있다.

★ 이건 제안일 뿐이고, 채택 여부와 전환 범위는 사용자가 결정한다.
  services/ocr.py 는 이번에도 건드리지 않았다.
