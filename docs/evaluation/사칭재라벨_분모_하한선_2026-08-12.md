## 1. 사칭 40건 재라벨

### 방법
문구를 읽고 '무엇을 사칭했는가'를 사람이 적은 뒤, **그 제도명을 코퍼스 제목으로 조회**해
URL 을 채웠다. 못 찾으면 `none` 이다 — **URL 을 창작하지 않았다.**
시스템 실행 결과를 보고 라벨을 정하지 않았다.

### 결과

| 구분 | 건수 | case_id |
|---|---:|---|
| **doc** — 사칭당한 제도가 코퍼스에 실재 | **8** | S05 S09 S11 S29 S30 S32 S38 S39 |
| **none** — 제도 자체가 없음 (수사기관·가족·거래·창작 상품 사칭) | **21** | S01 S02 S06 S07 S10 S12 S17~S24 S26 S28 S33~S36 S40 |
| **none** — 제도는 실재하나 **코퍼스에 없음** | **11** | S03 S04 S08 S13 S14 S15 S16 S25 S27 S31 S37 |
| **scam** — 수법 경보문 (전 건 승계) | **40** | 전부 |

**핵심: 사칭 40건 중 doc 으로 찾아야 하는 건 8건뿐이다.** 나머지 32건은
공식 제도 문서를 못 찾는 게 정상이거나(21건), 수집이 필요하다(11건).

### 코퍼스에 없어 수집이 필요한 제도 (11건 → 10종)

건강보험료 환급(2) · 정부24 미환급금 · 국민연금 · 대환대출 · 긴급재난지원금 ·
민생회복 소비쿠폰 · 주민등록등본 발급 · 종합소득세 환급 · 건강보험 자격 · 모바일 신분증

**★ 전부 금융·행정 제도다.** counterscam112(경보문)로는 안 채워지고
금감원·국세청·건보공단 쪽 **제도 안내문**이 필요하다.

### ★ ①문서 부재 7건 재확인 — 6건이 사라졌다

| case | 재라벨 후 | 판단 |
|---|---|---|
| S04 국민연금 추가 지급 | `none` | 국민연금 일반 안내문이 코퍼스에 없음 |
| S07 특별지원금 당첨 | `none` | 창작 — 당첨 절차를 가진 제도 없음 |
| S08 건강보험료 환급 | `none` | 코퍼스 부재 |
| S24 연금 지급 지연 | `none` | 기초·국민연금 중 특정 불가 |
| S26 의원실 노쇼 | `none` | 거래 사칭 — 제도 아님 |
| **S32 난방비 특별지원금** | **`doc`** | **에너지바우처 — 진짜 문서 부재 사례로 남음** |
| S40 지자체 행사 참가비 | `none` | 거래 사칭 — 제도 아님 |

**7건 중 6건은 "문서가 없는 게 아니라 엉뚱한 문서를 찾고 있었던" 것이 맞았다.**
지적하신 그대로다. 진짜 문서 부재로 남는 건 **S32 1건**이다.

## 2. 분모 수정 — 구/신 병기

| 지표 | 확대 112건 구 라벨 | **신 라벨** | 홀드아웃 30건 |
|---|---:|---:|---:|
| doc 모수 | 81 | **66** | 25 → 25 |
| **근거 검색 성공률**(doc 분모) | 61/81 (75.3%) | **57/66 (86.4%)** | 18/25 (72.0%) → 동일 |
| **Top-5 정답 포함**(doc 분모) | 54/81 (66.7%) | **56/66 (84.8%)** | 15/25 (60.0%) → 동일 |
| *(구 방식) 전체 분모 성공률* | 69/112 (61.6%) | 69/112 (61.6%) | 19/30 (63.3%) |

분자도 함께 움직였다(61→57, 54→56). 모수에서 빠진 15건 중 4건은 원래 근거를
찾던 건이고, Top-5 는 오히려 +2 다 — 재라벨로 정답이 바로잡힌 건이 있어서다.

**"실사용 문자가 늘수록 수치가 자동으로 나빠지는 구조"는 끊었다.** `no_ref`(실사용 11건)와
`scam_only` 는 이제 doc 분모에 들어가지 않는다.

> **홀드아웃은 수치가 그대로다.** 재라벨을 평가셋 S01~S40 에만 했고 홀드아웃
> 사칭 10건(H21~H30)은 손대지 않았기 때문이다. **일관성을 위해 홀드아웃도
> 같은 방식으로 재라벨해야 한다** — 아직 안 했다.

### 판정

**어느 값도 "확신 오답 증가"로 기각되지 않는다.** 양쪽 세트에서 확신 오답이
하한과 무관하게 완전히 고정이다(1건 / 0건). 하한선은 **확신선 아래 구간만**
움직이므로 당연한 결과이기도 하다.

**새로 생기는 비용은 구간 오답이다.** 확대셋에서 12 → 18 → 28 → 36 으로 늘어난다.
이 건들은 화면에서 주황 `hold` — *"비슷한 자료는 찾았지만 / 같은 안내인지는
확인하지 못했어요"* 로 나간다. 확신을 주지는 않지만 **틀린 문서를 보여주는 것**은 맞다.

0.55 에서 두 세트 모두 검색 성공률 100% 가 되지만, 구간 오답이 3배(12→36)다.
**성공률과 오답이 정확히 맞바꿔지는 구조라, 어느 쪽을 살지는 사람이 정할 문제다.**
숫자만으로는 결정되지 않아 제안하지 않는다.

## 4. ★ 실험 중 발견한 것 — 확신 오답 1건의 정체 (S22)

확대셋의 확신 오답 1건을 열어 봤더니 **검색 실패가 아니라 표시 문제**였다.

```
문구  : "한국인터넷진흥원 보안공지입니다. 귀하의 기기가 악성코드에 감염되었습니다.
         첨부한 파일을 설치해 치료하세요."          ← KISA 사칭 문자
검색 1위: "KISA 보안공지를 사칭한 스미싱 문자 주의"   ← 바로 그 수법의 경보문
점수  : 0.7023  (확신선 0.679 초과)
결과  : verdict_hint = needs_check  →  화면 초록 "공식 자료를 찾았어요"
```

**시스템은 정확히 맞는 문서를 찾았다.** 이 문자가 사기라고 경고하는 바로 그
경보문이다. 그런데 화면에는 **"공식 자료를 찾았어요"(초록)** 로 나간다.
사용자는 "이 문자가 확인됐다"로 읽는다.

### 원인 — 경보문이 `OFFICIAL_DOCS` 에 들어가 있다

`match_embedding_docs` 는 `OFFICIAL_DOCS` 를 뒤진다. KISA 경보문이 거기 있으니
`official_source_found` 신호가 붙고, 확신선을 넘으면 `needs_check` 가 된다.
**"공식 기관이 낸 문서"와 "이 글이 사실이라는 근거"를 구분하지 못한다.**

이건 8/12 에 제안한 **3분류(A 제도 안내문 / B 사기 경보문 / C 정책 발표)** 가
필요한 이유를 그대로 보여주는 실증이다. B 가 `SCAM_CASES` 에 있었다면
`similar_scam_case`(주의) 로 떠서 빨강 경고가 됐을 것이다.

> 구 라벨에서는 이게 **오답으로 잡히지 않았다.** S22 의 구 `출처_URL` 이 바로 그
> 경보문이라 "정답을 찾았다"가 됐기 때문이다. 재라벨을 하고 나서야 드러났다.
> 앞선 보고들의 "확신 오답 0건"은 **이 사례를 놓친 상태의 값**이다.
