## 1. 왜 지금 이걸 보는가

`official_alert_matched`(2026-08-12 채택)는 `data_type == "warning_case"` 만 경보문으로
본다. `press_release` 24건은 지시대로 제외했다 — "업무협약 체결"·"출범 6개월 성과"
같은 것이 섞여 있어 통째로 경보문이라 부를 수 없었기 때문이다.

그 결과 **실측으로 확인된 누락 4건**이 있다.

| S12 · S28 · H23 | 25. 4. 28. 그놈 목소리, 치밀한 각본 주인공이 되시겠습니까 | `press_release` | 신호 안 붙음 |
| H27 | 24. 10. 16. 나도 모르는 사이에 내 휴대전화가 좀비 폰으로? | `press_release` | 신호 안 붙음 |

## 4. 반영 방식 — 문서 id 허용목록 (2026-08-13 반영 완료)

`ALERT_DOC_DATA_TYPES = {"warning_case"}` 에 `"press_release"` 를 **추가하지 않았다.**
24건이 전부 같은 `data_type` 이라 C 16건이 함께 딸려 오기 때문이다.
대신 `services/search.py` 에 **문서 id 허용목록**을 뒀다.

```python
ALERT_DOC_IDS = { …B 8건의 문서 id… }

def _is_alert_doc(doc) -> bool:
    return getattr(doc, "data_type", "") in ALERT_DOC_DATA_TYPES or doc.id in ALERT_DOC_IDS
```

이 형태여야 **"사람이 확인한 것만 들어간다"가 코드에서도 성립한다.** 새 문서가
자동으로 포함되지 않는 것이 이 자료구조의 목적이다 — 늘리려면 사람이 다시 분류해야 한다.

**회귀 방어**: `test_alert_allowlist_covers_only_reviewed_press_releases`
누군가 `ALERT_DOC_DATA_TYPES` 에 `press_release` 를 넣으면 즉시 실패한다.
허용목록 id 가 코퍼스에서 사라져도 실패한다(코퍼스가 바뀌면 재분류하라는 신호다).

**되돌리기**는 기존 스위치가 그대로 덮는다: `ALERT_DOC_AS_ATTENTION = False`.
