## 1. 진단 — 토큰별 기여도 분해

채점식(수정 전):
```
kws   = extract_keywords(text) - STOPWORDS
match = [k for k in kws if k in case._blob]      # 부분 문자열 포함
score = Σ _keyword_weight(k),  weight = log((N+1)/(df+1)) + 1.0
매칭  = score >= 5.0
```

H05 와 **동일한 원인**이다. 세 가지 결함이 겹쳐 있었다.

### 결함 1 — 중복 계상

`extract_keywords()` 는 `"계좌로"` 와 조사를 뗀 `"계좌"` 를 **둘 다** 내놓는다.
둘 다 사례 본문의 부분 문자열이라 **같은 단어가 두 번 점수에 더해졌다.**
어떤 조사 붙은 명사든 점수가 약 2배로 부풀었다.

### 결함 2 — df 를 매칭과 다른 방식으로 셈 (가장 심각)

df 는 **토큰 단위**로 세는데 매칭은 **부분 문자열**로 한다. 그래서 토큰으로는
한 번도 등장하지 않지만 부분 문자열로는 걸리는 단어가 `df=0` → 가중치 4.951 을
받았다.

```
실제 존재하는 토큰의 최대 가중치 : 4.258  (df=1, '접수')
df=0 인 단어의 가중치            : 4.951  ← 더 높다
```

**"사기 코퍼스에 아예 없는 흔한 말"이 가장 강한 사기 신호가 됐다.**
의도와 정반대다. B03 은 조사 `'하는'` 하나로 4.951 점을 받았다.

### 결함 3 — 요구하는 행위를 보지 않음

C11(통장협박)이 H05 와 매칭된 근거는 `'계좌'` 뿐이다. 통장협박은 *사기범이
피해자 계좌로 소액을 보내는* 수법이고, H05 는 *연금이 계좌로 입금되는* 안내다.
**수법이 정반대인데 명사 하나로 연결됐다.**

## 2. 수정 — (b) + (c) 채택, (a) 는 부분 채택

지시받은 세 방향 중 **(b) 수법 카테고리 일치 요구**를 주 축으로,
**(c) severity 를 수법 일치도로 산출**을 함께 적용했다.

### 왜 (b)+(c) 인가

세 결함 중 1·2 는 **순수한 구현 버그**라 어느 방향을 고르든 먼저 고쳐야 한다.
남는 결함 3 이 오판의 본질이고, 그것을 직접 겨냥하는 것이 (b) 다.
(c) 는 (b) 없이는 성립하지 않는다(일치도를 재려면 카테고리가 먼저 필요하다).

### (a) 를 주 방향으로 삼지 않은 이유 — 실측 결과 부적합

지시대로 **정상 코퍼스의 문서빈도 순으로** 불용어를 도출해 봤다
(`experiments/derive_admin_stopwords.py`, 평가셋·홀드아웃 미참조).

| DF 비율 | 토큰 수 | 예시 |
|---|---|---|
| 30% 이상 | 16개 | 2025, 보건복지부, 소관부처명:, 서비스요약: |
| 20~30% | 11개 | 이상, 그림, go, 이용, 인터넷 |
| 5~10% | 295개 | 장애, 40대, 수술, 저소득층 |

DF≥5% 로 자르면 **457개**가 나오는데, 정상 코퍼스 862건이 국립암센터
문서와 실태조사에 크게 치우쳐 있어 `치료·진단·증상·유방암·위암` 같은
**주제 어휘가 대량 포함**된다. 이걸 그대로 불용어로 쓰면 코퍼스 편중이
매칭 로직에 그대로 옮겨붙는다.

지시서가 예시로 든 `계좌·지급·신청·안내·기관·정부·확인` 중 실제로 고DF 로
도출된 것은 일부뿐이었다. **(a) 는 이 코퍼스에서 원하는 목록을 만들어 내지
못한다** — 그대로 보고한다. 기존 STOPWORDS 9개는 유지했다.

### 구현

**`api/services/scam_taxonomy.py` (신규)** — 공개 자료 기반 9개 수법 카테고리.
출처: 금융감독원 보이스피싱 지킴이, 경찰청 전기통신금융사기 유형,
범정부 통합대응단, 식약처 부당광고 기준. **평가셋·홀드아웃 미참조.**

핵심은 **비대칭 판정**이다.

| | 판정 방식 | 이유 |
|---|---|---|
| 사용자 입력 | (대상 명사 ∧ **요구 동작**) | 사기 문자 *원문* 이라 명령형이 살아 있다. 엄격해야 정상 안내문과 갈린다 |
| 사기 사례 | 대상 명사만 (주제 수준) | 사람이 쓴 *서술형 요약* 이라 명령형이 없다. 똑같이 엄격하면 진짜 사례까지 탈락한다 |

그리고 수동·수령 표현(`입금되며`, `지급됩니다`, `등록하신`)은 자금이체·선입금
카테고리에서 **제외**한다. 이것이 핵심 판별자다.

```
정상 "등록하신 계좌로 입금되며"   → 요구 없음 → 매칭 0건
사칭 "안전계좌로 수수료를 보내세요" → 자금이체·선입금 요구 → 대조 진행
```

**`api/services/corpus_index.py`**
1. `_dedup_morph_variants()` — 조사 변형과 원형을 하나로 (결함 1)
2. `_scam_substring_df()` — df 를 매칭과 **같은 부분 문자열 규칙**으로 계산 (결함 2)
3. 수법 카테고리 게이트 — 입력이 아무 수법도 요구하지 않으면 즉시 종료 (결함 3)
4. 점수를 `(수법 일치 개수, 어휘 가중치)` 튜플로 — 어휘는 순위 결정용 보조 (c)
5. 본문 없는 레코드 제외 (아래 §4)

**임계값 `min_score=5.0` 은 값을 바꾸지 않았고, 이제 판정에 쓰지 않는다.**
이 값은 중복 계상이 있던 시절 분포에 맞춰진 값이라, 버그를 고치자 점수가
전반적으로 내려가 그대로 쓰면 **사칭까지 탈락했다**(실측: S02 매칭 0건).
값을 내려 맞추는 것도 결국 임계값 조정이므로, 판정 축 자체를 카테고리로 옮겼다.

## 5. 데이터 위생 — 본문 없는 사기 사례 19건

`SCAM_CASES` 51건 중 **19건이 스크랩 메타데이터뿐**이다.

```
' 끈 떨어지는 상담소  고수익을 약속하는 투자의 함정 담당부서신고대응센터
  2026-07-24 12 첨부 이미지 또는 문서 3개 투자유도'
```

실제 수법 설명이 없어 어휘가 겹쳐도 근거가 되지 않는다.

**정정(2026-08-05)**: 초판에 "19건 제외 → 실질 36건"이라고 적었으나
산술이 맞지 않았다. 19 는 엄격 판정(`detect_categories`) 기준 미검출
수이고, 실제 게이트는 주제 판정(`describe_categories`)을 쓴다.

| 구분 | 건수 |
|---|---|
| 전체 | 51 |
| 본문 온전 (`origin="relabeled"`) | 30 |
| **본문 결손** (`origin="public_data_warning"`) | **21 (전부)** |
| **실질 대조 대상** | **36** = relabeled 30 + warning 6 |
| 대조에서 제외 | 15 |

`public_data_warning` 21건은 **전부** 본문이 비어 있다. 그중 6건은
제목에 수법 명사가 있어 대조 대상에는 남지만 본문이 없는 건 마찬가지다.
재수집 대상은 21건 전부다. 상세: `docs/evaluation/corpus_gaps.md` §4
