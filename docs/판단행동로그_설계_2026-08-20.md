# 판단 행동 로그 (judgment_logs) 설계

2026-08-20 · 구현·배포 완료

## 1. 왜 새 표인가 — events 와 무엇이 다른가

| | `events` (2026-08-05) | `judgment_logs` (2026-08-20) |
|---|---|---|
| 단위 | 행동 낱개 (진입·클릭·이탈) | **세션 1개당 1행** |
| 묻는 것 | 화면을 어떻게 썼나 | **판단을 어떻게 했나** |
| 대표 지표 | 체류시간·이탈률·첫클릭시간 | 질문을 열었나·무엇을 확인했나·무엇을 골랐나 |
| 비교축 | 화면(S1~S5) | **baseline / training / posttest** |

`session_id` 를 같은 값으로 주면 두 표가 조인된다. 그래서 "S3 에서 오래 머물렀는데
질문은 열지 않았다" 같은 것을 볼 수 있다.

## 2. 필드

| 컬럼 | 타입 | 채우는 곳 | 비고 |
|---|---|---|---|
| `session_id` | PK str(64) | 클라이언트 | 없으면 `chk:<check_id>` 로 대체 |
| `user_ref` | str(64) | 서버 | `sha256(device_id)` — `check_store` 와 같은 값 |
| `session_type` | str(16) | 클라이언트 | baseline / training / posttest. **서버가 임의로 안 채운다** |
| `input_type` | str(16) | 서버 | photo / link / text / voice |
| `questions_shown` | int | 서버 | 질문을 내보낸 횟수 |
| `question_opened` | bool? | 클라이언트 → 서버 대체 | ★ 성급 판단의 역지표 |
| `checked_source/author/date/condition` | bool? | 클라이언트 | ★ NULL = 미측정 |
| `check_count` | int? | 서버 | 위 넷 중 True 개수. 전부 미보고면 **NULL** |
| `decision` | str(16) | 클라이언트 | apply / share / hold / not_apply / ask_family |
| `time_to_decision` | float? | 서버 | 세션 시작~판단(초) |
| `misjudge_tag` | str(32) | 서버 | `tagger` 의 오판 유형 |
| `card_id` / `card_result` | str(40)/str(16) | 클라이언트 | correct / wrong / skipped |
| `created_at` | datetime | 서버 | 세션 시작 |

## 3. ★ 지시서와 실물이 어긋난 것 (실물을 따랐다)

지시서의 값 목록이 지금 서비스와 세 군데 어긋났다. 실물을 따르고 여기 적는다.

### (가) `input_type`: photo / link / **voice**

실제 입력 경로는 `image` · `link` · `text` 세 가지다.

- `image` → **`photo`** 로 이름만 맞춰 저장한다.
- **`text`(붙여넣기)는 지시서에 없었지만 넣었다.** 실제로 가장 많이 쓰이는 경로라
  빼면 대부분의 세션이 `input_type=NULL` 로 남는다.
- **`voice` 는 지금 API 에 경로가 없다.** 값만 열어 뒀고, 오늘 기준으로는
  **한 건도 쌓이지 않는다.** (평가셋 CSV 의 `입력채널=음성` 은 평가용 라벨이지
  API 입력 경로가 아니다.)

### (나) `decision`: 신청 / **공유** / 보류 / 안함

기존 `Decision` 리터럴은 `apply` · `not_apply` · `hold` · `ask_family` 다.

- 신청 = `apply` · 보류 = `hold` · 안함 = `not_apply` — 그대로 대응된다.
- **공유 = `share` 는 지금 화면에 버튼이 없다.** 값만 열어 뒀다.
- ★ **`ask_family`(가족에게 물어보기)를 '공유'로 접지 않았다.**
  가족에게 묻는 것과 남에게 퍼뜨리는 것은 정반대 행동이다. 하나로 세면
  전파 위험 지표가 통째로 뒤집힌다.

### (다) `session_type`: baseline / training / posttest

서비스에 이 구분 자체가 없다. **클라이언트가 보내야만** 값이 생긴다.
서버가 기본값으로 `baseline` 을 채우지 않는다 — 안 보낸 것을 baseline 으로 세면
"훈련 후에 좋아졌다"는 방향으로 데이터가 오염된다.

## 4. ★★ NULL 은 '아니오'가 아니라 '측정하지 않음'이다

`checked_*` 와 `question_opened` 는 nullable 이다. 클라이언트가 보고하지 않으면
`False`(=확인 안 함)가 아니라 NULL 로 남는다.

> 보고가 없는 것을 False 로 저장하면, 프론트가 아직 안 붙은 오늘 시점에
> **"아무도 출처를 확인하지 않았다"** 는 수치가 그럴듯하게 만들어진다.
> 측정하지 않은 것을 측정한 것처럼 만들지 않는다.

집계(`summarize`)는 NULL 을 표본에서 뺀다. 그리고 **모든 비율에 표본 수를 함께**
돌려준다 — "3명 중 1명"과 "300명 중 100명"이 똑같이 0.333 으로 보이지 않도록.

## 5. `question_opened` 를 어떻게 재는가 — 한계 포함

"화면에 떴다"와 "사람이 열어서 읽었다"는 다르다.

1. 클라이언트가 `question_opened` 를 보내면 **그 값을 쓴다** (가장 정확).
2. 없으면 **답을 했는지(`user_reply`)** 로 대체한다.

★ 2번의 한계: **열어서 읽었지만 답하지 않고 바로 결정한 경우를 못 잡는다.**
그 경우 NULL 로 남지 False 가 되지는 않는다. 정확한 값이 필요하면 프론트가
1번을 보내야 한다.

## 6. 개인정보

- **자유 텍스트 컬럼이 하나도 없다.** 문자열 컬럼 8개는 전부 해시·UUID·짧은 코드값이다.
- 허용 목록에 없는 값은 **잘라 넣지 않고 버린다.** 자르면 자유 텍스트의 앞부분이
  그대로 남는다("어머니 통장 비밀번호가…" → "어머니 통장 비").
- `user_ref` 는 `sha256(device_id)`. `check_store.hash_device` 와 **같은 값**이다 —
  다른 해시를 쓰면 같은 사람이 표마다 다른 사람으로 세어진다.
- 보관 90일. `tools/purge_old_records.py` 대상에 **같은 커밋에서** 넣었다.
- 삭제는 `tools/delete_rows.py` 대상 표에 **같은 커밋에서** 넣었다.

이 두 가지(자유 텍스트 컬럼 없음 · 허용 목록 밖 값 버림)는
`api/tests/test_judgment_log.py` 가 자동으로 지키고,
**가드 자신이 실패하는지도 같은 파일에서 시험한다**
(`test_guard_itself_fails_when_free_text_column_added`).

## 7. 계측은 흐름을 막지 않는다

`events` 와 같은 fire-and-forget 계약이다. 모든 예외를 삼키고 서버만 `ST-003` 으로
인지한다.

★ 첫 구현에서 `db = SessionLocal()` 이 `try` **밖**에 있었다. 커넥션 풀이 마르면
세션을 만드는 그 줄에서 예외가 나 라우터로 올라가고, **확인 화면이 500 이 된다.**
계측 때문에 서비스가 죽는 것이다.
`test_recording_failure_never_raises` 가 잡았고 컨텍스트 매니저로 고쳤다.

## 8. 프론트가 보내야 할 것 (아직 안 보내도 동작한다)

| 엔드포인트 | 추가 필드 | 없으면 |
|---|---|---|
| `POST /checks` | `session_id`, `session_type` | `chk:<check_id>` 로 대체 · session_type NULL |
| `POST /checks/{id}/dialogue` | `session_id`, `question_opened` | 대체 키 · 답변 여부로 대체 |
| `POST /checks/{id}/verdict` | `session_id`, `checked_*` 4종 | 대체 키 · checked_* 전부 NULL |
| `POST /training/result` | `session_id`(필수), `card_id`, `result` | ★ 이 경로는 대체 키가 없어 미기록 |

★ 전부 선택(마지막 것만 예외)이라 **프론트 변경 없이도 오늘부터 기록이 쌓인다.**
다만 그 상태에서는 `checked_*` · `session_type` · `card_*` 가 전부 NULL 이다 —
**이 표의 핵심 지표 절반이 프론트 연동에 달려 있다.**

## 9. 집계

`GET /api/v1/judgments/summary` — ★ **운영자 전용**(`X-Admin-Token`).
`?session_type=posttest` 로 좁힐 수 있다. `events/summary` · `errors/summary` 와
같은 게이트를 쓴다.
